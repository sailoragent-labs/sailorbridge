# 플로 및 예약 이벤트

플로를 사용하면 팀이 같은 절차로 작업을 반복할 수 있습니다. 채팅에서 입력할 수 있는 이름이 있으며 해당 팀에 단계와 옵션이 저장됩니다. 예약 이벤트는 지정한 시각에 팀 채팅으로 메시지를 보냅니다. 그 메시지로 리더에게 질문하거나 플로를 시작할 수 있습니다.

## 플로 찾아 실행하기

팀 채팅에 `/`를 입력하면 활성화된 플로와 설명이 표시됩니다. 플로를 고르고 원하는 작업을 덧붙여 보냅니다. 예를 들어 `/ask What should the export include?`를 보내면 그 요구 사항에 대한 대화가 시작됩니다. 대화형 플로는 채팅에서 질문합니다. 백그라운드 플로는 **작업 목록**에 들어갑니다.

백그라운드 플로 명령을 보내면 **리더**가 보통 대화를 바탕으로 작업 설명을 작성하고 대기열에 넣습니다. 해당 플로의 **바로 시작** 옵션이 켜져 있으면 입력한 내용이 그대로 작업 설명이 되고 즉시 대기열에 들어갑니다. 기본 제공 백그라운드 플로에서는 이 옵션이 기본으로 꺼져 있습니다. 리더가 먼저 작업을 제안했다면 **네, 진행**을 선택해 시작합니다.

| 기본 제공 플로 | 사용 방법과 결과 |
| --- | --- |
| `/ask` | 결정할 사항을 명확히 합니다. 질문에 하나씩 답하면 요구 사항 요약을 받습니다. |
| `/plan` | 여러 작업이 필요한 일을 계획합니다. 계획과 제안된 작업 묶음을 읽고 **모두 대기열에 넣기**, **계획 수정** 또는 **지금은 실행 안 함**을 선택합니다. 계획을 세우는 작업 자체의 진행 상황도 확인할 수 있습니다. |
| `/agent` | 반복적이거나 시간이 오래 걸리는 일을 워커에게 맡깁니다. 워커 한 명이 수행하고 검토 라운드 없이 결과를 보고합니다. |
| `/write-review` | 구현 작업을 팀에 맡기고 검사 방법을 설명합니다. 작성자가 작업하고 검사가 실행되면 작성자와 검토자가 결과를 확인합니다. |
| `/memory-tidy` | 팀 메모리를 검토해 가치가 없어진 항목을 삭제하고 중복 항목을 합칩니다. 납품 보고서에는 취한 조치와 사용자의 결정이 필요한 제안이 나옵니다. 확인할 항목이 있으면 팀에서 자동으로 실행할 수도 있으며, 24시간에 최대 한 번 실행합니다. |
| `/docs-tidy` | 변경의 영향을 받는 문서를 다시 확인하고 나머지 문서를 돌아가며 표본 점검합니다. 납품 보고서에는 기계적으로 수정한 부분과 질문을 구분해 적습니다. |
| `/code-sweep` | 코드에서 정리할 부분을 찾습니다. 납품 보고서의 번호가 붙은 제안을 읽고 어떤 것을 실행할지 리더에게 알려 줍니다. 점검 자체는 읽기 전용입니다. |
| `/write-flow` 및 `/edit-flow` | 반복할 작업을 설명해 플로를 만들거나 기존 플로를 어떻게 바꿀지 설명합니다. 결과는 해당 팀에 저장됩니다. |

## 작성자와 검토자 선택하기

팀 채팅에서 ⋯를 열고 **팀 플로**를 선택한 뒤 `/write-review`를 엽니다. 이 팀의 이후 작업에 쓰일 단계와 옵션이 표시됩니다.

| 옵션 | 사용 방법 |
| --- | --- |
| **누가 작성하나요** | **자동**을 유지해 작업 난이도에 따라 제공업체를 고르거나, 작성 단계에 쓸 엔진을 지정합니다. |
| **누가 검토하나요** | **자동**을 유지해 다른 모델 계열의 독립 검토자를 찾거나, 검토에 쓸 엔진을 지정합니다. 자체 검토는 작성자가 수행합니다. 실제 모델은 팀의 모델 설정에서 정합니다. |
| **자체 검토 횟수** | 0~10회이며 기본값은 3입니다. 라운드마다 작성자가 작업을 확인하고 발견 사항을 수정한 뒤 다시 검사합니다. 발견 사항이 없거나 설정한 횟수에 이르면 끝납니다. 0으로 설정하면 자체 검토를 건너뜁니다. |
| **최대 몇 라운드** | 0~10라운드이며 기본값은 6입니다. 0으로 설정하면 Solo가 되어 독립 검토를 건너뛰고 자체 검토 설정을 유지합니다. |

P1 발견 사항이 나오면 전체 변경 사항을 다시 검토해야 합니다. 그보다 낮은 등급은 수정한 부분을 검토합니다. 3라운드부터는 P1이 없으면 작성자가 나머지 사항을 수정하고 추가 검토 없이 납품할 수 있습니다. 라운드 한도에 도달했는데 P1이 남아 있으면 **납품 보고서**를 열어 작업이 중단된 이유가 된 발견 사항을 확인합니다.

코드를 병합하려면 마지막 커밋에서 적용되는 검사를 모두 통과해야 합니다. 문서만 바뀌었고 적용되는 검사가 없다면 독립 검토자가 그 이유를 인정해야 합니다. Solo에서는 실행할 검사가 없는 변경이 **미완료** 상태로 남습니다. [작업 검사 및 납품 보고서 읽기](jobs.md)

## 팀 플로 작성 또는 수정하기

1. 팀 채팅에서 `/write-flow` 뒤에 단계, 완료 조건, 단계가 실패했을 때의 대응 및 납품할 내용을 적어 보냅니다. 예를 들어 `/write-flow List Markdown files changed since the last commit. Report their paths. If none changed, say so.`를 보냅니다.
2. 작성자에게 결정이 필요하면 채팅에서 질문에 답합니다. 플로 작성과 검사가 끝나면 저장된 이름이 채팅에 표시됩니다. **플로 보기**를 선택해 설명, 단계 및 옵션을 읽습니다. 이 이름은 이제 `/` 메뉴에서 사용할 수 있습니다.
3. 플로를 수정하려면 **채팅에서 편집**을 선택하거나 `/edit-flow <name> <change>`를 보냅니다. 무엇을 바꾸고 무엇을 유지할지 설명합니다. 사용자 지정 플로를 수정하면 해당 팀의 버전이 교체됩니다. 기본 제공 플로를 수정하면 다른 이름으로 사용자 지정 플로가 만들어집니다. 납품 보고서에서 실제 적용된 옵션값과 수정 중 빠진 단계 규칙을 확인합니다.

플로 상세 페이지에서도 옵션을 수정할 수 있습니다. 저장된 지시에 따라 실행하는 플로라면 다음 실행에 적용할 지시를 그곳에서 수정할 수 있습니다. **활성화**를 끄면 팀 메뉴에서 해당 플로를 새로 실행할 수 없게 됩니다. 대기 중이거나 실행 중인 작업은 완료할 수 있습니다. 플로를 작성하고 수정하는 두 명령은 계속 사용할 수 있습니다.

## 메시지 예약하기

1. 팀의 ⋯ 메뉴에서 **예약 이벤트**를 열고 더하기 버튼으로 **이벤트 추가**를 선택합니다. **전할 내용**에 보낼 메시지를 최대 16 KiB까지 입력합니다. 예를 들어 `/docs-tidy Check the project documentation.`를 입력합니다.
2. **빈도**를 설정합니다. 현지 기준 미래의 날짜와 시각을 지정하려면 **한 번**, 매일 같은 시각에 보내려면 **매일**, 월요일부터 금요일까지 보내려면 **평일**을 선택합니다. **몇 분마다**를 선택하면 **반복 간격(분)** 항목을 5~720으로 설정합니다. 하루 중 일부 시간에만 보내려면 **시작**과 **종료**를 사용합니다.
3. 처음에는 브라우저 설정을 따르는 **시간대**를 확인하고 저장합니다. 목록에는 메시지의 첫 줄과 다음 실행 시각이 표시됩니다. 이벤트를 만들면 메시지 전송을 승인한 것으로 처리됩니다. 정해진 시각에 메시지가 내 이름으로 채팅에 표시되고 **예약** 표시가 붙습니다. 한 번 발생할 때마다 리더의 채팅 차례 하나를 모두 사용합니다.

시각은 선택한 시간대를 따릅니다. 일광 절약 시간 전환으로 예약 시각을 건너뛰면 다음 유효한 시각에 실행합니다. 같은 시각이 두 번 나오면 첫 번째 시각을 사용합니다. 간격이 지정된 이벤트에 시간 범위가 있으면 그 밖의 실행은 건너뜁니다.

이벤트를 열어 메시지나 시각을 수정합니다. 저장하면 다음 실행 시각을 다시 계산합니다. 앞으로 보낼 메시지를 멈추려면 이벤트를 끄고 재개하려면 다시 켭니다. 다시 켠 시점부터 일정이 적용됩니다. 예약 서비스가 중단된 뒤에는 놓친 실행 중 가장 최근의 한 건만 전송합니다. 텍스트나 `#6` 같은 정확한 번호로 이벤트를 검색합니다. 끝난 일회성 이벤트는 **실행 완료**에서 찾습니다.

## 문제가 생겼을 때

- 채팅에서 플로를 인식하지 못하면 `/`를 입력해 이 팀에서 활성화된 이름을 확인합니다. 필요하면 **팀 플로**에서 플로를 다시 활성화합니다. `/write-review`가 비활성화되어 계획의 작업을 대기열에 넣을 수 없으면 플로를 활성화한 뒤 작업을 다시 제출합니다.
- 팀마다 사용자 지정 플로를 최대 30개 만들 수 있습니다. 한도에 도달하면 쓰지 않는 사용자 지정 플로를 지운 뒤 새 플로를 만듭니다. 이미 쓰는 이름이라면 해당 플로를 수정하거나 다른 이름을 선택합니다. 수정 중 빠진 단계 규칙이 너무 길어 납품 보고서에 넣을 수 없다고 나오면 플로 페이지에서 규칙을 줄이거나 옮긴 뒤 다시 시도합니다.
- 팀마다 예약 이벤트를 최대 20개 등록할 수 있습니다. 한도에 도달했다면 이벤트를 삭제한 뒤 추가합니다. 일회성 이벤트가 이미 실행되었다면 새로 만들어 반복합니다. 미래의 시각과 위 범위에 해당하는 간격을 사용합니다.
- 예약 메시지가 없거나 비활성화된 플로 또는 존재하지 않는 번호를 지정하면 해당 회차는 소진됩니다. 다음 실행 전에 메시지를 고치거나 플로를 활성화합니다. 예약된 대화형 플로가 다른 플로가 실행 중이라고 보고하면 이후 실행 시각까지 대기합니다.
