# 작업

플로를 한 번 실행하면 작업 하나가 됩니다. 한 팀의 머신은 하나의 대기열을 공유합니다. 채팅에서 팀에 작업을 맡기고 번호로 진행 상황을 찾을 수 있습니다. 납품 보고서를 열어 결과와 추가로 살펴볼 사항을 확인합니다.

## 작업을 대기열에 넣기

팀 채팅에서 플로 이름과 할 일을 함께 보냅니다. 예를 들어 `/agent Count the files at the top level of this project and report the count.`를 보냅니다. 작업이 대기열에 들어가면 실행 가능한 머신이 여유가 있을 때 가져갑니다. 머신은 자체 작업용 복사본에서 작업을 실행합니다.

**리더**가 대화에서 작업을 제안하면 내용을 읽고 **네, 진행**을 선택해 대기열에 넣습니다. 여러 작업이 있는 계획은 목록을 읽은 후 **모두 대기열에 넣기**를 선택합니다. **계획 수정**으로 바꿀 점을 설명할 수 있습니다. **지금은 실행 안 함**을 선택하면 그 작업 묶음을 대기열에 넣지 않습니다. 승인하면 각 작업에 고유 번호가 붙습니다. [플로 선택](flows-and-scheduled-events.md)

## 작업 찾고 상태 읽기

팀 채팅의 ⋯ 메뉴에서 **작업 목록**을 선택하거나 채팅에 표시된 작업의 **자세히 보기**를 선택합니다. 목록에는 처음에 **실행**이 표시되며 이후에는 이 브라우저에서 마지막으로 쓴 필터를 기억합니다. 종료된 작업도 보려면 **전체**를 선택합니다. 작업 내용이나 플로 이름으로 검색하거나 `#6`처럼 해시 기호를 포함한 전체 번호를 입력해 필터와 관계없이 찾을 수 있습니다.

| 표시 | 의미 |
| --- | --- |
| **대기** | 머신이 작업을 가져가기를 기다립니다. 아래 줄에 이유가 표시됩니다. 다른 작업 번호가 있으면 그 작업이 먼저 끝나야 합니다. |
| **실행** | 머신이 작업을 가져갔습니다. 작업을 열어 현재 단계와 머신을 확인합니다. |
| **리더 대기 중** 또는 **응답 대기** | 리더는 답할 수 있는 질문을 처리합니다. 내 결정이 필요하면 **답하기**를 선택하고 채팅에서 답변합니다. **응답** 필터로 내 답변을 기다리는 작업을 찾습니다. |
| **완료** | 플로가 결과를 납품했습니다. **완료, 검사 통과 못함**은 납품된 결과에 실패한 검사가 있다는 뜻입니다. 결과를 사용하기 전에 해당 검사를 확인합니다. |
| **미완료** | 요청한 모든 내용을 납품하기 전에 멈췄습니다. 멈춘 지점과 빠진 내용을 확인합니다. 이미 한 작업은 보관됩니다. |
| **실패** | 오류로 실행이 종료됐습니다. 보고서와 **머신 메모**를 열어 이유를 확인합니다. |
| **취소** | 작업이 중지됐습니다. 해당 항목은 목록에서 계속 볼 수 있습니다. |

**일시 중지됨**과 **한도**도 작업이 대기 중인 이유일 수 있습니다. **실행 중이 아닌 이유**를 열어 기다리는 이유와 취할 수 있는 조치가 있는지 확인합니다.

## 작업 세부 정보, 납품 보고서 및 사용량 읽기

번호가 붙은 행을 선택합니다. **작업 상세**에서 상태, **실행** 및 **라운드**를 볼 수 있습니다. **작업 정보**에는 머신, 작업을 시작한 사람, **대기**가 포함됩니다. **단계**를 펼치면 실행된 단계, 걸린 시간, 사용된 엔진 및 모델을 볼 수 있습니다. **품질 문제**가 표시되는 경우 자체 검토, 독립 검토 및 마지막 독립 검토 라운드의 발견 사항을 확인할 수 있습니다.

작업이 끝나면 **납품 보고서**를 엽니다. **변경 사항**, **검사**, **검토 의견**, **미확인** 및 **결정 필요**를 읽습니다. 완료된 작업에 실패한 검사가 있으면 먼저 표시됩니다. 커밋을 생성한 작업은 커밋이 반영된 곳을 확인합니다. 머신이 푸시하지 못했다면 보고서에 로컬 브랜치와 커밋, 실패 이유, 실행할 수 있는 명령이 표시됩니다. 보고서만 필요한 작업은 커밋 없이 답변을 납품할 수 있습니다.

**사용량**을 열고 **라운드별 내역**을 펼쳐 토큰 수와 실제로 사용된 모델을 확인합니다. 사용량은 제공업체, 계정 및 모델별로 기록됩니다. 납품 보고서의 합계는 머신이 마지막으로 작업을 가져간 시점부터의 사용량입니다. 대기 시간과 실행 시간은 별도로 기록됩니다.

## 작업 일시 중지, 변경, 중지 또는 계속하기

- 대기 중인 작업에서 **일시 중지**를 선택하면 머신이 가져가지 않습니다. 다시 실행할 수 있을 때 **재개**를 선택합니다. **지금 시작**을 선택하면 대기 중인 작업을 맨 앞으로 옮깁니다. 실행 자리가 모두 차 있으면 계속 기다리거나 실행 중인 작업을 직접 중지해 자리를 확보할 수 있습니다.
- 열린 작업을 바꾸려면 작업에서 **채팅으로 이동**을 선택합니다. 해당 번호가 자동으로 입력됩니다. 새 요구 사항을 덧붙여 메시지를 보냅니다. 리더가 변경을 제안하면 **네, 변경**을 선택합니다. 대기 중인 작업은 설명이 제자리에서 바뀝니다. 실행 중이면 현재 실행을 멈추고 같은 번호로 대기열에 다시 넣습니다.
- 작업을 끝내려면 **중지**를 선택하고 확인합니다. 직접 멈춘 작업을 계속하려면 새 지시가 필요합니다. 종료된 작업의 재개 지점과 사용할 수 있는 결과가 남아 있다면 ⋯ 메뉴에서 **계속**을 선택합니다. 동일한 작업 번호와 보관된 작업용 복사본 또는 푸시된 브랜치를 사용합니다. 계속하기 전에 요구 사항을 바꾸면 처음부터 시작합니다.
- **다시 실행**을 선택하면 원래 플로, 작업 설명, 저장소, 옵션으로 새 작업을 대기열에 넣습니다. 새 번호가 부여되며 이전 작업도 계속 볼 수 있습니다. **계속**을 사용할 수 없을 때 이용합니다. **삭제**를 확인하면 종료된 작업 기록을 영구 삭제합니다.

## 문제가 생겼을 때

- 팀 전체의 배정이 일시 중지되었다면 머신이 새 작업을 가져가도록 **배정 재개**를 선택합니다. 팀 또는 계정이 동시 실행 한도에 도달했다면 자리가 생길 때 시작합니다. [팀 배정 설정](teams.md)
- 작업이 답변을 기다리는 경우 처음 5분이 지나도 답할 수 있습니다. 5분이 지나면 머신이 실행 자리를 비웁니다. 답변한 뒤 원래 머신에 여유가 생기는 즉시 작업이 재개됩니다.
- 작업에 작성자나 검토자가 필요하면 **계정으로 이동**을 선택합니다. 한 머신에 전체 작업에 필요한 계정이 있어야 합니다. 모든 후보 머신이 작업을 거절하면 작업이 실패하고 메모에 각 머신의 이유가 표시됩니다. 할당량이나 속도 조절 때문에 대기한다면 예상 시각을 확인합니다. 할당량이나 실행 자리가 생기면 작업이 재개됩니다. [엔진 계정 및 작업 속도 조절](engine-accounts-and-pacing.md)
- 머신이 연결을 잃어도 다시 연결되면 이어서 실행할 수 있습니다. 작업을 맡고 있는 상태가 30분 동안 갱신되지 않으면 다른 팀 머신이 작업을 가져가 처음부터 시작할 수 있습니다. 같은 작업에서 연결이 3번 끊기면 **실패** 상태로 종료됩니다. 계속하거나 다시 실행하기 전에 머신을 확인합니다. [머신 확인](machines.md)
- 복구 가능한 시스템 오류는 작업 하나가 진행되는 동안 최대 10회 자동으로 계속할 수 있습니다. 작업이 종료된 채로 남아 있으면 마지막 보고서를 읽고 원인을 해결한 뒤 **계속** 옵션이 있을 때 선택합니다.
