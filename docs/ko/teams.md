# 팀

팀을 만들면 한 프로젝트에서 **리더**와 대화할 채팅, 작업 대기열, 팀 메모리, 한 대 이상의 머신을 따로 사용할 수 있습니다. 여러 팀을 소유하거나 같은 머신을 여러 팀에서 쓸 수 있습니다. 내 팀의 설정을 보고 바꿀 수 있는 사람은 나뿐입니다.

## 프로젝트용 팀 만들기

1. 리더를 실행할 머신을 페어링합니다. **온라인**으로 표시되면 페어링 페이지에서 **팀 만들기**를 선택합니다. **팀**에서 **팀 만들기**를 선택해 시작할 수도 있습니다. [머신 페어링](machines.md)
2. **팀 이름**을 입력하고 해당 머신을 선택합니다. 머신에서 사용할 수 있는 **아바타**와 리더 계정, 모델 및 추론 강도를 선택하거나 기본값을 사용합니다.
3. **프로젝트 디렉터리**에 선택한 머신의 `/`로 시작하는 절대 경로를 입력합니다. 이미 저장소에서 작업 중이라면 해당 로컬 디렉터리를 사용합니다. 기존 원격 저장소에서 작업하려면 먼저 해당 머신에 복제하고 Git 인증 정보를 설정합니다. SailorBridge가 저장소의 메인 브랜치를 감지합니다.
4. **결과 대상**을 선택한 뒤 **팀 만들기**를 선택합니다. 이제 팀에 해당 머신이 표시됩니다. **채팅**을 열어 리더와 대화합니다. [팀 채팅 사용](chat.md)

팀이 처음 해당 경로를 사용하면 기존 폴더를 열거나, 폴더가 없으면 생성합니다. 파일이 있는 일반 폴더라면 Git을 초기화하고 최초 스냅샷을 만듭니다. 폴더 바로 아래에 Git 저장소가 여러 개라면 어느 저장소인지 리더에게 알려 줍니다. 작업 하나는 저장소 하나에서 실행됩니다. 여러 저장소에 걸친 일은 별도 작업으로 나뉩니다.

## 변경 사항을 보낼 곳 정하기

**팀**에서 내 팀을 열어 **팀 상세**로 이동합니다. 이곳에서 **프로젝트 디렉터리**나 **결과 대상**을 바꿀 수 있습니다. 변경은 머신이 다음에 가져가는 작업부터 적용됩니다.

| 결과 대상 | 작업의 커밋을 찾는 곳 |
| --- | --- |
| **자동 병합**(기본값) | 머신은 원격 메인 브랜치에 푸시를 시도하고 로컬 메인 브랜치를 빨리 감기합니다. 원격 메인 브랜치에 새 커밋이 있거나 원격에서 검토를 요구하면 납품 보고서를 확인합니다. 작업 브랜치가 나와 있으면 원격에서 그 브랜치를 병합합니다. |
| **브랜치** | 작업마다 별도의 `sb/<job>` 브랜치에 푸시되며 직접 검토하고 병합할 수 있습니다. 다른 작업은 프로젝트의 메인 브랜치에서 시작합니다. |

각 머신은 저장소에 설정된 Git 원격과 인증 정보를 사용합니다. 작업 전 원격 메인 브랜치를 가져오며, 가능하면 로컬 복사본을 빨리 감기합니다. 푸시에 실패하면 작업의 **납품 보고서**를 열어 이유, 로컬 브랜치, 커밋, 푸시 명령을 확인합니다. [작업의 납품 보고서 찾기](jobs.md)

## 머신 추가, 이동 또는 제거하기

**팀 상세**에서 **머신 목록**을 열고 더하기 버튼으로 **머신 추가**를 선택합니다. 페어링된 머신을 고른 뒤 **팀 폴더와 동일**을 선택하거나 **프로젝트 폴더**에 그 머신의 절대 경로를 입력합니다. 경로는 나중에 바꿀 수 있습니다. 조건을 충족하고 여유가 있는 머신은 이제 같은 대기열에서 작업을 가져올 수 있습니다.

팀에서 머신을 빼려면 해당 머신을 선택하고 **팀에서 제외**를 확인합니다. 이 머신은 해당 대기열에서 새 작업을 가져오지 않습니다. **리더가 이 머신에서 실행됨**으로 표시된 머신을 팀에서 빼거나 사용을 중단하면 남은 머신 중 가장 먼저 팀에 들어온 머신이 리더를 맡습니다. 팀의 마지막 머신은 제거할 수 없습니다. 대체할 머신부터 추가합니다.

## 팀이 작업을 받는 방식 설정하기

팀의 작업 실행 방식을 변경하려면 **팀 상세**로 돌아갑니다.

- **작업 설정**의 **배정**에서 새 작업을 제어합니다. **일시 중지됨**을 선택하면 대기 중인 작업은 보류되고 실행 중인 작업은 계속됩니다. **정상**을 선택하면 머신이 대기열에서 다시 작업을 가져옵니다.
- **동시 작업 수**의 기본값은 **제한 없음**이므로 계정의 동시 실행 한도가 적용됩니다. **개수 지정**을 선택해 이 팀에서 동시에 실행할 작업 수를 제한합니다. 수를 낮추면 실행 중인 작업이 끝나면서 적용됩니다.
- **리더 모델**에서 계정을 선택한 다음 모델과, 제공되는 경우 추론 강도를 선택합니다. 계정은 해당 머신과 함께 표시됩니다. 다른 팀 머신의 계정을 고르면 다음 메시지부터 리더가 그 머신으로 옮겨갑니다. 같은 대화 요약과 팀 메모리를 사용합니다. 실행 중인 작업은 원래 머신에서 계속됩니다.
- 워커의 경우 난이도 및 제공업체마다 선호하는 모델과, 제공되는 경우 추론 강도를 선택합니다. **기본값으로 되돌리기**를 선택하면 해당 설정이 팀 기본값으로 돌아갑니다. **계정 목록**에서 계정을 작성, 검토 또는 리더 용도로 제한할 수 있습니다. [엔진 계정 및 작업 속도 조절](engine-accounts-and-pacing.md)

## 팀 해산하기

**팀 상세**를 열고 **팀 해산**을 선택합니다. 종료될 Agent 세션 수를 확인한 뒤 팀 이름을 입력해 확정합니다. 해산은 되돌릴 수 없습니다. 열린 작업이 취소되고 예약 이벤트가 삭제되며 목록과 채팅 진입점에서 팀이 제거됩니다. 해당 팀의 대기 중인 Agent 세션 요청과 활성 세션도 종료됩니다. 각 참가자는 세션 기록을 유지합니다. 머신은 계정에 페어링된 상태로 남습니다.

## 문제가 생겼을 때

- 선택할 머신이 없다면 팀을 만들 때 **머신 페어링**, 머신을 추가할 때 **새 머신 페어링**을 선택합니다. 사용을 중단한 머신이라면 다시 페어링한 뒤 추가합니다.
- 작업이나 채팅에서 디렉터리를 만들 수 없다고 나오면 해당 경로를 사용하려 한 머신에서 확인합니다. 그 위치에 파일이 있거나, 쓰기 권한이 없거나, 디스크가 읽기 전용이면 생성할 수 없습니다. **팀 설정에서 디렉터리 변경**을 선택하고 해당 머신에서 쓸 수 있는 디렉터리를 입력합니다.
- 팀을 만드는 동안 리더의 계정이나 모델을 더 이상 사용할 수 없게 되면 갱신된 목록에서 다시 고릅니다. 팀을 만든 뒤에도 작업이 대기 중이라면 작업 상세에서 **실행 중이 아닌 이유**를 읽고 배정, 한도 또는 계정 중 무엇이 원인인지 확인합니다.
