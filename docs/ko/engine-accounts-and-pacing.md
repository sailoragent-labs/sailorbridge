# 엔진 계정 및 작업 속도 조절

Agent는 내 머신에 로그인된 엔진 계정을 사용합니다. 팀이 사용할 수 있는 계정, 남은 할당량, 작업이 재개될 시각을 확인할 수 있습니다. SailorBridge 요금제에 따라 동시에 실행할 수 있는 Agent 수가 정해집니다. 모델 이용 권한과 할당량은 엔진 제공업체가 정합니다.

## 계정 찾기 또는 추가하기

1. 실행할 머신에서 Claude Code 또는 Codex에 로그인합니다. `sail account list`를 실행합니다. 기본 로그인은 자동으로 감지됩니다. 이름은 보통 엔진 이름 뒤에 `@`와 머신 이름을 붙인 형태입니다.
2. 다른 로그인을 추가하려면 별도의 계정 디렉터리에서 엔진에 로그인합니다. `sail account add <name> <directory>`에 디렉터리와 이름을 지정합니다. 이름은 해당 머신에서 중복되지 않아야 하며 공백이나 슬래시가 없는 1~64자여야 합니다. 예를 들어 두 번째 로그인이 해당 경로에 있다면 `sail account add work "$HOME/codex-work"`를 실행합니다. 재시작할 필요 없이 다음 할당량 확인 시 새 계정을 인식합니다.
3. **리소스**를 열고 **계정**을 선택합니다. 계정을 선택하면 해당 머신, 할당량 및 사용 가능한 모델을 볼 수 있습니다. 여러 머신에서 같은 엔진이 같은 이름으로 보고한 계정은 한 행에 표시됩니다. 로그인 디렉터리, 이메일, 인증 정보는 머신에 남습니다.

Codex는 구독 로그인을 사용합니다. Claude Code는 구독 로그인 또는 API 키를 사용할 수 있습니다. Gemini CLI, Copilot CLI, OpenCode, Qwen Code, Pi는 계정 등록과 로컬 확인만 지원합니다. 이 5개 중 Gemini CLI와 OpenCode는 이름을 지정한 별도 디렉터리를 인식합니다.

## Claude 호환 엔드포인트 사용하기

DeepSeek나 GLM 같은 제공업체를 사용하려면 머신에서 별도의 Claude Code 계정 디렉터리를 설정합니다. 해당 디렉터리의 `settings.json`에서 제공업체의 기본 URL을 `env.ANTHROPIC_BASE_URL`에, 인증 정보를 `env.ANTHROPIC_API_KEY` 또는 `env.ANTHROPIC_AUTH_TOKEN`에 설정합니다. 같은 `env` 객체에서 `ANTHROPIC_MODEL`을 제공업체의 모델 이름으로 설정합니다. `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL`, `ANTHROPIC_DEFAULT_HAIKU_MODEL`로 Opus, Sonnet, Haiku 계열을 각각 매핑할 수 있습니다.

해당 머신에서 선택한 이름과 경로를 지정해 `sail account add <name> <directory>`를 실행합니다. 계정은 Claude Code를 통해 실행됩니다. **사용 가능한 모델**을 열면 디렉터리에서 읽어 온 모델 이름이 표시됩니다. 엔드포인트 모델에는 이 매핑이 적용되며 추론 강도 설정은 제공되지 않습니다. 작업 상세에는 실제로 실행된 모델이 표시됩니다.

## 템플릿으로 GLM, DeepSeek 또는 Kimi 계정 설정

`sail account create`는 제공업체의 엔드포인트, 상·중·하 등급의 제안 모델, 키 자리표시자를 담은 로컬 Claude Code 설정 파일을 작성합니다. 이 명령은 키를 요청하거나 읽거나 전송하지 않으며 계정도 등록하지 않습니다.

GLM을 설정하려면 계정을 사용할 머신에서 다음 명령을 실행합니다.

```sh
sail account create glm
```

명령은 3줄을 출력합니다. 여기서 `~`는 홈 디렉터리를 뜻합니다.

```text
제안 모델(Opus/Fable, Sonnet, Haiku/하위 에이전트): glm-5.3, glm-5.2, glm-5.3-flash.
서로 다른 모델 ID가 세 개입니다. Sonnet에는 중간 등급으로 제안된 모델을 사용합니다.
~/.sailorbridge/account-templates/glm/settings.json에서 자리표시자를 본인의 API 키로 바꾼 후 sail account add <name> ~/.sailorbridge/account-templates/glm 명령을 실행하세요.
```

생성된 `settings.json`에는 다음 템플릿이 들어 있습니다.

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "REPLACE_WITH_YOUR_API_KEY",
    "ANTHROPIC_BASE_URL": "https://api.z.ai/api/anthropic",
    "ANTHROPIC_MODEL": "glm-5.3",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "glm-5.3",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "glm-5.2",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "glm-5.3-flash",
    "ANTHROPIC_DEFAULT_FABLE_MODEL": "glm-5.3",
    "CLAUDE_CODE_SUBAGENT_MODEL": "glm-5.3-flash"
  }
}
```

`nano` 같은 텍스트 편집기로 파일을 엽니다.

```sh
nano ~/.sailorbridge/account-templates/glm/settings.json
```

`REPLACE_WITH_YOUR_API_KEY`를 본인의 GLM 키로 바꾼 뒤 따옴표를 유지한 채 저장합니다. 원하는 이름으로 디렉터리를 등록합니다. 이 예에서는 `glm`을 사용합니다. 이름은 머신에서 중복되지 않아야 하고 1~64자여야 하며 공백 문자나 `/`를 포함할 수 없습니다.

```sh
sail account add glm ~/.sailorbridge/account-templates/glm
sail account list
```

터미널 목록에서 `glm`을 찾습니다. 머신이 계정을 보고하면 앱에서 **리소스**를 열고 **계정**을 선택합니다. `glm`을 선택해 **사용 가능한 모델**을 확인합니다.

DeepSeek 또는 Kimi의 경우 해당 제공업체의 명령부터 실행합니다. 출력된 경로의 `settings.json`을 열고 자리표시자를 제공업체의 키로 바꿉니다. 출력된 `sail account add` 명령에 원하는 이름을 지정해 실행한 뒤 `sail account list`로 확인합니다.

| 템플릿 생성 명령 | 파일의 엔드포인트 | 출력되는 제안 모델 |
| --- | --- | --- |
| `sail account create deepseek` | `https://api.deepseek.com/anthropic` | 상위 등급은 `deepseek-v4-pro`를 사용합니다. 중간 및 하위 등급은 `deepseek-flash`를 함께 사용합니다. |
| `sail account create kimi` | `https://api.kimi.com/coding/` | Kimi Coding Plan의 키를 사용합니다. 세 등급 모두 `k3.1-pro[1m]`을 사용합니다. |

MiniMax에는 `--region international` 또는 `--region china` 옵션이 필요합니다. GLM, DeepSeek, Kimi는 `--region` 옵션을 허용하지 않습니다.

## 할당량을 확인하고 직접 쓸 몫 남겨 두기

**계정**에서 계정을 엽니다. **할당량**, **재설정**, **측정**을 함께 확인합니다. 구독 조회 결과에는 5시간 단위 한도, 주간 한도 또는 특정 모델의 주간 할당량이 표시될 수 있습니다. Codex는 표준 주간 할당량을 보고합니다. 할당량을 읽는 데 모델 토큰이 들지 않습니다. 새 조회가 실패하면 최대 1시간 전의 성공 결과가 이전 값임을 나타내는 표시와 함께 나타날 수 있습니다. 조회 결과가 없으면 그 이유가 표시되며, 계정은 여전히 작업을 받을 수 있습니다.

- **사용 허용** 설정으로 내 모든 팀에서 이 계정에 새 작업을 배정할 수 있는지 제어합니다. 끄더라도 이미 실행 중인 작업은 마칠 수 있습니다.
- **예약 기준선** 설정으로 직접 사용할 몫을 비율로 남겨 둡니다. 0%에서 100%까지 5%포인트 단위로 설정합니다. 하루보다 긴 기간의 남은 할당량이 이 비율 이하가 되면 워커와 **리더** 모두 해당 계정의 사용을 중단합니다. 짧은 기간의 할당량은 모두 사용할 수 있습니다.
- 지출로 측정하는 계정은 **월 한도**에 해당 머신이 한 달 동안 사용할 최대 금액을 설정합니다. 예를 들어 DeepSeek에 적용됩니다. GLM은 자체 할당량 조회 결과를 제공합니다. 한도에 도달하면 한도를 올리지 않는 한 새 작업은 다음 달 1일 UTC 자정까지 대기합니다. 이미 진행 중인 단계는 한도를 넘어도 완료할 수 있습니다. 같은 계정을 여러 머신에 등록하면 각 머신이 지출을 별도로 측정합니다. **비용 계산 불가**로 표시되면 토큰 수는 볼 수 있지만 한도는 적용되지 않습니다.
- Claude 또는 Codex에서 보고하면 **리셋권**이 표시됩니다. 리셋권을 열어 초기화 대상과 만료 시각을 확인한 뒤 **사용**을 선택하고 확정합니다. 계정 목록에서 **리셋 사용**을 선택하면 사용할 수 있는 리셋권 중 먼저 만료되는 항목을 사용합니다. 계정이 있는 머신에서 초기화합니다. 다른 리셋권을 사용하기 전에 결과를 확인합니다.

## 팀별로 계정과 모델 고르기

팀 채팅 메뉴에서 **계정 목록**을 엽니다. 팀 머신의 계정은 기본으로 포함됩니다. **역할**을 **둘 다**, **작성만** 또는 **검토만**으로 설정하여 이 계정을 사용할 수 있는 워커 단계를 지정합니다. **리더 전용**을 사용하면 이 팀의 채팅에만 계정을 사용합니다. **팀에서 제외**, **팀에 계정 추가**를 사용해 이 팀에서 계정을 사용할 수 있는지 변경합니다.

**팀 상세**에서 배정 설정을 엽니다. **리더 모델**에서 팀 머신의 활성 계정을 선택한 뒤 감지된 모델과 선택 가능한 추론 강도를 고릅니다. 다른 머신의 계정을 고르면 다음 메시지부터 **리더**가 그 머신으로 이동합니다. 선택한 계정이 실행할 수 없으면 답변에 대신 사용한 엔진과 모델이 표시됩니다.

워커의 경우 팀 모델 설정에서 난이도와 엔진마다 선호하는 모델과 추론 강도를 설정합니다. 플로의 작성 및 검토 옵션에서 엔진을 선택합니다. 자동 검토를 사용하면 검토자는 가능하면 작성자가 실제로 사용한 모델 계열을 피합니다. 플로에서 지정한 엔진을 해당 역할에 쓸 계정이 팀에 없으면 그 실행에 한해 자동 선택을 사용할 수 있습니다. 작업 상세에서 변경 이유를 설명합니다.

작업의 모든 단계를 한 머신에서 수행할 수 있어야 합니다. 그 머신에서 각 단계는 해당 엔진과 역할에 대해 사용이 허용된 활성 계정을 사용합니다. 조건을 충족하는 계정 중에는 로그인 갱신을 기다리는 계정이 먼저입니다. 그다음은 하루 안에 초기화되는 계정으로, 초기화가 빠른 순입니다. 이후에 초기화되는 계정은 가용 할당량, 요금제 용량, 초기화까지 남은 시간을 고려해 선택합니다. 조회 결과가 없는 계정은 마지막입니다. 변경분만 검토하거나 변경된 줄이 120줄 이하인 첫 검토에서는 여유가 있는 작은 요금제를 우선합니다.

## 새 작업의 속도 설정하기

**리소스**를 열고 **속도 제한 방식**을 선택합니다. 기본값인 **할당량에 맞춤**은 할당량이 적용되는 기간에 걸쳐 작업을 나눕니다. 사용한 할당량의 비율이 경과 시간의 비율보다 100/7%포인트(약 14.3%포인트) 넘게 앞서고 기간이 7분의 1 넘게 남아 있으면 계정이 기준 속도를 초과한 상태입니다. 사용할 수 있는 모든 계정이 기준 속도를 초과하면 머신은 새 작업을 가져오기 전에 대기합니다. 이미 실행 중인 작업과 **리더**와의 채팅은 계속할 수 있습니다.

**제한 없음**을 선택하면 모든 팀이 속도 기준에서 기다리지 않고 새 작업을 가져옵니다. 계정의 예약 할당량과 이미 소진된 구간의 제한은 계속 적용됩니다. 내 팀 중 하나라도 **리더**용으로 선택한 계정 전체에 적용되는 할당량이 10% 미만으로 남으면 워커는 그 계정을 채팅용으로 남겨 둡니다. 같은 화면에서 **할당량에 맞춤**으로 돌아갈 수 있습니다.

## 문제가 생겼을 때

- 템플릿 파일이 이미 있으면 명령은 덮어쓰지 않고 경로를 출력합니다. 기존 파일을 편집한 뒤 그 디렉터리를 등록합니다.
- 명령이 디렉터리 사용을 거부하면 출력된 경로를 확인합니다. 나만 접근할 수 있도록 해당 디렉터리의 소유자가 내 사용자여야 하며 권한은 `0700`이어야 합니다. 소유자와 권한을 수정한 뒤 템플릿 생성 명령을 다시 실행합니다.
- `sail uninstall`는 설정 파일을 포함한 `~/.sailorbridge/`를 삭제하므로 키 사본을 다른 곳에도 보관합니다.
- 등록에 실패하면 제공한 디렉터리에 대해 터미널에 표시된 로그인 명령을 따릅니다. 디렉터리는 하나의 엔진으로 인식되어야 합니다. `sail account list`로 이름을 확인합니다. 등록을 제거하거나 기본 로그인을 무시하려면 `sail account remove <name>`를 실행합니다. 로컬 인증 정보는 유지됩니다. 기본 로그인을 다시 인식하게 하려면 `sail account restore claude` 또는 `sail account restore codex`를 실행하거나 머신의 **무시된 로그인**을 열고 **복원**을 선택합니다.
- **로그인 만료**로 표시되면 지정된 머신에서 다시 로그인합니다. **로그인 갱신 필요**로 표시되면 머신이 갱신을 시도합니다. **네트워크 사용 불가**로 표시되면 해당 머신의 연결을 확인합니다. 제공업체에 요청 한도가 걸리거나 이용할 수 없다면 잠시 뒤 재시도합니다. 모델 선택 화면에 계정이 **모델을 아직 읽지 못함**으로 표시되면 조회를 기다리거나 모델이 감지된 계정을 선택합니다.
- 팀에서 **리더** 계정을 제거할 수 없다면 먼저 **리더 모델**에서 다른 계정을 선택합니다. 작업에 작성자나 검토자가 부족하면 상세에서 **계정으로 이동**을 선택하고 전체 작업을 할 수 있는 머신에서 필요한 역할을 활성화합니다.
- **작업 목록**을 열고 **실행 중이 아닌 이유**를 읽습니다. 속도 조절로 대기할 때는 예상 시각이 표시됩니다. 계속 기다리거나 모든 팀에 적용되는 **제한 없음으로 전환** 선택을 확정할 수 있습니다. 사용할 수 있는 계정의 할당량이 소진된 작업은 같은 머신에서 표시된 시각까지 대기한 뒤 다시 확인합니다. 로그인하거나 할당량을 다시 얻으면 자동으로 재개됩니다.
