# 문제 해결

작업이 멈춘 곳부터 확인합니다. 로그인이나 결제 문제라면 해당 화면의 메시지를 읽습니다. 머신 문제라면 해당 머신의 터미널을 확인합니다. 작업 문제라면 **작업 목록**에서 작업을 선택하고 **실행 중이 아닌 이유**를 읽습니다. 직접 조치해야 하는지 자동으로 재개되는지 알 수 있습니다.

## 계정에 다시 접근하기

| 표시되는 내용 | 조치 |
| --- | --- |
| 선장 ID가 이미 사용 중이거나 오늘 등록 한도에 도달함 | 사용 가능한 다른 ID를 시도합니다. 그날의 무료 가입 한도에 도달했다면 내일 다시 시도합니다. 유료 ID라면 원래 **교환 링크**를 사용해 가입을 마칩니다. |
| 비밀번호 입력 후 **본인 확인** 화면이 표시됨 | 인증 앱을 사용하거나, 페어링된 머신에서 `sail confirm`를 실행하여 표시된 코드를 입력합니다. 숫자 대조 방법이 제공되면 인식된 브라우저에서 표시된 숫자를 선택합니다. 가장 최근의 로그인 요청을 사용합니다. 만료되면 다시 로그인합니다. |
| 로그인 실패가 너무 많거나 이미 사용한 인증 앱 코드를 입력함 | 15분 안에 5회 실패하면 기본 15분 동안 잠깁니다. 표시된 시간까지 기다립니다. 인증 앱 코드를 이미 사용했다면 다음 코드를 기다립니다. |
| 비밀번호를 잊었거나 복구 코드가 만료됨 | 페어링된 머신의 터미널에서 `sail recover`를 실행합니다. **비밀번호를 잊으셨나요?** 항목을 선택하고 터미널에 표시된 선장 ID와 8자 코드를 입력합니다. 코드는 10분 동안 한 번만 쓸 수 있습니다. 같은 머신에서 새 코드를 받으면 이전 코드를 대체합니다. 머신의 인증 정보가 거부되면 페어링된 다른 머신을 시도합니다. 사용할 수 있는 페어링된 머신이 없으면 새 ID로 가입해야 합니다. |
| **계정 복구 적용 대기 중** | 페어링한 지 72시간이 안 된 머신에서는 72시간을 기다려야 합니다. 복구 과정에서 인증 정보가 교체된 경우에도 해당합니다. 더 오래전에 페어링했으며 2단계 인증을 켠 지 72시간 이상이라면, 즉시 복구하려면 인증 앱 코드가 필요합니다. 코드가 없으면 72시간 복구 요청을 제출합니다. 표시된 시간까지 기다립니다. 본인이 복구를 요청하지 않았다면 로그인한 기기에서 **이번 복구 취소**를 선택합니다. |

## 머신 또는 팀이 작동하게 하기

- Git이 없어 설치가 중단되면 Git을 설치하고 **새 머신 페어링**의 명령을 다시 실행합니다. Claude Code나 Codex가 로그아웃 상태여도 페어링은 완료할 수 있습니다. 팀에 작업을 요청하기 전에 머신에서 `claude login` 또는 `codex login`을 실행합니다.
- 페어링 코드가 만료되면 `sail login`으로 새 코드를 받습니다. **새 머신 페어링**에서 코드를 입력하고 **페어링**을 선택한 뒤 화면에 표시된 머신 이름과 세부 정보를 확인합니다. 첫 페어링이라면 안내를 읽고 동의한 뒤 **머신 승인**을 선택하고 머신이 연결될 때까지 기다립니다.
- 머신이 10분 안에 연결되지 않으면 `sail host status`를 실행합니다. 서비스 상태와 로그 경로가 표시됩니다. 같은 주소에서 서비스를 복구하려면 `sail login`을 실행합니다. `origin_mismatch`가 표시되고 주소를 바꾸려는 경우 `sail uninstall`을 실행하면 작업용 복사본을 포함한 로컬 SailorBridge 데이터가 제거됩니다. 이후 연결할 앱의 **머신** 페이지에 있는 설치 명령을 실행해 다시 페어링합니다.
- 업데이트에 실패하면 **머신**에서 해당 머신을 열고 이유와 복구 명령을 따릅니다. 다운로드에 실패했다면 나중에 `sail upgrade`로 다시 시도합니다. 쓰기에 실패했다면 디스크 공간을 확인하고 `sail`을 설치한 계정을 사용합니다.
- 팀을 만들 때 머신을 요구하면 한 대를 페어링하고 **온라인** 상태가 될 때까지 기다립니다. 팀의 마지막 머신을 제거할 수 없으면 먼저 **머신 추가**를 사용합니다. 팀 디렉터리를 만들 수 없다면 **팀 설정에서 디렉터리 변경**을 선택합니다. 오류가 발생한 머신의 절대 디렉터리 경로를 사용합니다. 해당 경로에 파일이 있거나 쓰기 권한이 없거나 디스크가 읽기 전용이면 디렉터리를 만들 수 없습니다. [머신](machines.md) · [팀](teams.md)

## 채팅에서 답변 받기

- **리더**의 머신이 오프라인이라면 팀 채팅에서 메시지를 저장했다가 해당 머신이 다시 연결되면 전달합니다. 팀에 사용할 머신이 없으면 추가하고 메시지를 다시 보냅니다.
- 엔진에 로그인이 필요하다면 지정된 머신에서 로그인합니다. **리더**가 사용할 수 있는 모든 계정이 할당량을 소진했다면 초기화 시각 이후에 메시지를 다시 보냅니다. 모델이 거부되면 엔진 업데이트 안내에 따라 다시 시도하거나 사용할 수 있는 계정과 모델을 고릅니다. [엔진 계정 및 작업 속도 조절](engine-accounts-and-pacing.md)
- 메시지가 **리더**에게 가는 대신 질문의 답변으로 전달되었다면 열린 질문에 답하거나 해당 카드에서 **중지**를 선택합니다. 그런 다음 메시지를 보냅니다. 확인 카드가 교체되었거나 이미 답변되었다면 작업하기 전에 최신 카드나 작업을 확인합니다.
- 파일이 거부되면 팀 채팅에서 메시지당 첨부 파일을 최대 4개, 각 5 MiB 이하로 보냅니다. PNG, JPEG, WebP, PDF, 일반 텍스트, Markdown을 지원합니다. 사용할 수 없는 첨부 파일은 다시 선택합니다. 보내지 않은 업로드는 24시간 뒤 만료됩니다. 계정의 1 GiB 한도에 도달하면 보낸 파일이 30일 후 만료되어 공간이 생기기를 기다립니다. 메시지가 너무 크면 각각 64 KiB 이하의 메시지로 나눕니다.
- Agent 세션에서 계정에 로그인이나 할당량이 필요했다면 먼저 해결하고 **재개**를 선택합니다. 팀 간 세션이 라운드 제한에 도달하면 받은 사람이 10 또는 20라운드를 연장하거나 **라운드 무제한**을 선택할 수 있습니다. 시작한 사람은 받은 사람의 조치를 기다립니다. [채팅](chat.md)

## 작업이 대기 중인 이유 찾기

**작업 목록**에서 작업을 엽니다. 다시 시작할지 결정하기 전에 **실행 중이 아닌 이유**를 읽습니다.

| 작업이 지연되는 이유 | 조치 |
| --- | --- |
| 배정이 일시 중지되었거나 이 작업이 일시 중지됨 | 팀은 **배정 재개**를, 개별 작업은 **재개**를 사용합니다. |
| 머신이 사용 중이거나 팀이 작업 수 한도에 도달했거나 요금제의 Agent 한도에 도달함 | 실행 자리가 생기면 작업이 시작됩니다. 팀은 **동시 작업 수**를, 계정은 **동시 실행 한도** 항목을 **구독**에서 확인합니다. |
| 작업에 작성자와 검토자가 필요함 | **계정으로 이동**을 선택합니다. 팀 머신 한 대에서 두 단계에 필요한 계정을 모두 사용할 수 있게 합니다. 작성자와 검토자가 다른 머신에 있으면 같은 작업을 함께 수행할 수 없습니다. |
| 머신이 속도 기준에 도달했거나 할당량을 소진함 | 표시된 예상 시각까지 기다립니다. 속도 조절로 대기 중이면 **제한 없음으로 전환**을 확정한 후 모든 팀의 속도 설정이 바뀝니다. 할당량을 소진한 경우 작업이 다시 확인하고 할당량이 돌아오면 같은 머신에서 재개합니다. |
| 답변이나 선행 작업이 필요함 | 내게 온 질문이면 **답하기**를 선택합니다. 답변을 5분 기다린 뒤 작업은 실행 자리를 비웁니다. 답변하면 원래 머신에 여유가 있을 때 이어서 실행합니다. 선행 작업이 필요하면 표시된 작업 번호를 열어 결과를 확인합니다. |
| 머신이 작업을 거절했거나 연결이 끊김 | 작업 아래의 이유를 읽습니다. 조건을 충족하는 다른 머신이 거절된 작업을 가져갈 수 있습니다. 모든 후보가 거절했다면 **머신 메모**를 열어 각 머신의 이유를 확인합니다. 작업 중 연결이 끊긴 머신이 먼저 돌아오면 재개할 수 있습니다. 30분 동안 작업을 맡은 상태가 갱신되지 않으면 다른 머신이 처음부터 시작할 수 있습니다. |
| **미완료** 또는 **실패** | **납품 보고서**를 열어 마지막 단계와 이유, 보관된 결과를 확인합니다. 보고된 문제를 해결합니다. **계속** 옵션이 있으면 보관된 결과로 같은 작업을 이어서 실행하거나 **다시 실행**을 사용해 처음부터 시작합니다. 푸시에 실패했다면 보고서에는 로컬에 보관된 작업의 브랜치, 커밋, 푸시 명령이 표시됩니다. |

## 명령, 예약 이벤트 또는 메모리 항목의 문제 해결

- 터미널에 “이 명령은 작업이나 팀 리더 세션 안에서 실행하세요.”(`local_team_context_missing`)라고 표시되면 팀 디렉터리에 있어도 명령을 실행할 활성 세션이 필요합니다. 팀 채팅에서 **리더**에게 요청하거나 **작업 목록**, **예약 이벤트** 또는 **팀 메모리**를 열어 기존 항목을 다룹니다. [번호가 붙은 팀 항목의 명령](commands.md#번호가-붙은-팀-항목-다루기)
- 슬래시 명령을 알 수 없다고 나오면 `/`를 입력해 활성화된 플로를 확인합니다. 번호 참조가 없다는 메시지가 나오면 팀과 항목 유형이 맞는지 확인하고 채팅에서 번호 앞에 `#`을 붙입니다. `sail exec`가 대상이 오프라인이라고 보고하면 명령은 시작되지 않은 상태입니다. 시작한 *후에* 결과가 사라졌다면 다시 시도하기 전에 대상 머신을 확인합니다. [명령](commands.md)
- 예약 이벤트가 거부되면 일회성 이벤트에는 미래 시각을, 반복 이벤트에는 5~720분 간격을 지정합니다. 한 팀에는 이벤트를 최대 20개 등록할 수 있습니다. 불필요한 이벤트를 지워 자리를 만듭니다. 완료된 일회성 이벤트를 다시 실행하려면 새로 만들어야 합니다. 이벤트가 비활성화된 플로나 존재하지 않는 번호를 지정했다면 다음 실행에 사용할 메시지를 고칩니다. [플로 및 예약 이벤트](flows-and-scheduled-events.md)
- 메모리 변경이 거부되면 **팀 메모리**를 엽니다. 잠긴 항목은 그곳에서 직접 수정할 수 있습니다. 다른 사람이 먼저 수정했다면 저장 전에 최신 본문을 읽습니다. 고정 용량이 가득 찼다면 항목의 고정을 해제하거나 내용을 줄인 뒤 다른 항목을 고정합니다. [팀 메모리](team-memory.md)

## 처리되지 않은 결제 확인하기

결제가 대기 중이면 다시 결제하기 전에 원래 구매로 돌아가 상태를 확인합니다. 구독에 **결제 실패**가 표시되면 **결제 수단 변경 및 미납금 결제**를 선택해 미결제 금액을 납부하는 결제 화면을 엽니다. [요금제 및 결제](plans-and-billing.md)

## 문제가 생겼을 때

문제가 계속되면 진행한 단계, 정확한 메시지, 예상했던 결과 및 문제가 발생한 위치를 기록합니다. 버전, 머신 운영체제, 엔진을 아는 경우 함께 적습니다. 계정이나 결제 문제는 README에 있는 비공개 연락처를, 보안 문제는 그곳의 비공개 보안 링크를 사용합니다. 공개 보고에 인증 정보, 페어링 코드, 결제 세부 정보 또는 비공개 소스 코드를 넣지 않습니다. [문제 신고](README.md#문제-신고)
