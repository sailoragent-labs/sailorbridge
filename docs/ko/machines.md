# 머신

머신은 팀의 리더를 실행하거나 작업을 가져오도록 계정에 연결하는 컴퓨터입니다. 각 머신에 `sail`을 설치하고 브라우저에서 승인합니다. 터미널을 닫아도 백그라운드 서비스가 연결을 유지합니다.

## 머신 설치 및 페어링

1. 직접 관리하는 Linux x64 또는 macOS(arm64 또는 x64) 머신을 사용합니다. Git을 설치합니다. 채팅과 작업을 하려면 Claude Code 또는 Codex를 설치하고 해당 머신에서 본인의 엔진 계정으로 로그인합니다. 엔진에 로그인하기 전에 페어링을 완료해도 됩니다.
2. 앱에서 **머신**을 열고 **새 머신 페어링**을 선택합니다. 화면의 설치 명령을 연결할 머신의 터미널에 복사합니다. 어느 디렉터리에서든 실행할 수 있습니다. `sail`을 설치하고 페어링을 시작하며 10분 동안 유효한 8자 코드를 출력합니다.
3. 브라우저에서 **페어링 코드**에 코드를 입력하고 **페어링**을 선택합니다. 머신 이름과 **키 코드**가 터미널에 표시된 값과 일치하는지 확인합니다. 처음 페어링할 때는 안내를 읽고 동의합니다. Agent는 `sail`을 실행하는 운영체제 사용자의 권한으로 파일을 읽고 수정하고 삭제하며, 인증 정보를 사용하고 네트워크에 연결할 수 있습니다. 격리가 필요하면 전용 머신이나 컨테이너를 사용합니다.
4. **머신 승인**을 선택합니다. 머신이 인증 정보를 받고 서비스를 시작하는 동안 연결을 유지합니다. **머신**에 **온라인**으로 표시되고 터미널에도 접속이 확인되면 **계정 설정** 또는 **팀 만들기**를 선택할 수 있습니다. [팀 만들기](teams.md)

## 연결 확인 또는 다른 머신 페어링

**머신**에서 머신을 열어 이름, 플랫폼, **마지막 온라인**, **페어링 일시**, **클라이언트 버전**을 확인합니다. 머신을 더 쉽게 구분하도록 이름을 바꿀 수 있습니다. 해당 머신에서 `sail host status`를 실행하면 페어링, 연결, 서비스 상태를 확인하고 로컬 로그의 위치를 찾을 수 있습니다.

다른 컴퓨터를 사용하려면 **새 머신 페어링**을 다시 열고 그 컴퓨터에서 표시된 명령을 실행합니다. 온라인이 되면 팀에 추가하고 해당 머신의 프로젝트 폴더를 설정합니다. 머신 하나는 여러 팀에서 사용할 수 있습니다. 각 작업은 팀에서 실행 가능한 머신 한 대에서 실행됩니다. [팀 머신 관리](teams.md)

## 설치 업데이트 또는 복구

자동 업데이트는 기본으로 켜져 있습니다. 업데이트를 검증한 뒤 서비스가 재시작되고 로컬 작업을 다시 시작합니다. 완료된 단계는 유지됩니다. 중단된 로컬 단계는 다시 실행될 수 있습니다. 수동 업데이트는 머신에서 `sail upgrade`를 실행합니다. 업데이트를 설치했는지, 이미 최신 버전이었는지, 오류가 발생했는지 알려 줍니다. 설치된 버전을 확인하려면 `sail --version`을 실행합니다.

서비스를 복구하려면 `sail login`을 실행합니다. 같은 주소에서는 기존 인증 정보로 서비스를 다시 설치하고 재시작합니다. 인증 정보가 거부되고 머신이 여전히 등록되어 있으면 복구 페어링이 시작됩니다. 브라우저에 **기존 머신 다시 페어링**과 교체 대상 머신이 표시됩니다. 내용을 확인한 뒤 새 코드를 승인합니다. 머신은 기존 팀에 남습니다. 새 인증 정보를 받으면 그 시점이 비밀번호 복구에 사용하는 새 페어링 날짜가 됩니다.

## 머신 사용 중단 또는 제거

계정 전체에서 머신 사용을 중단하려면 **머신**에서 해당 행의 메뉴를 열고 **삭제**를 선택한 뒤 확인합니다. 인증 정보가 취소되고 머신은 팀에서 빠지며, 알림을 받으면 작업을 멈춥니다. 연결 중이면 즉시, 연결이 끊긴 상태라면 다음 접속 시 알림을 받습니다. 로컬 작업용 복사본은 유지됩니다. 다시 사용하려면 해당 머신에서 `sail login`을 실행한 뒤 새 페어링을 승인하고 필요한 팀에 추가합니다.

컴퓨터에서 제거하기 전에 SailorBridge 작업용 복사본에 있는 필요한 작업을 저장합니다. 해당 머신에서 `sail uninstall`을 실행합니다. 서비스가 중지되고 `sail`, 서비스 정의, 설치 프로그램이 셸에 추가한 경로 항목, `~/.sailorbridge/` 디렉터리 전체가 제거됩니다. 인증 정보, 계정 등록, 로그, 로컬 채팅 기록, 작업용 복사본, `sail` 백업도 포함됩니다. 본인의 프로젝트 디렉터리와 엔진 로그인 디렉터리는 유지됩니다. 다시 설치하려면 **새 머신 페어링**의 명령을 사용합니다.

## 문제가 생겼을 때

- 페어링에 Git이 없다고 표시되면 Git을 설치하고 `sail login`을 실행해 계속합니다. 엔진에 로그인되어 있지 않으면 채팅이나 작업을 시작하기 전에 `claude login` 또는 `codex login`으로 별도로 로그인합니다.
- 코드가 만료되면 `sail login`으로 새 코드를 받습니다. 머신 이름이나 **키 코드**가 다르면 **페어링 취소**를 선택하고 대상 머신의 터미널을 확인합니다. 승인이 완료됐는데도 10분 내에 연결되지 않으면 `sail host status`를 실행한 뒤 `sail login`으로 다시 연결합니다.
- 머신이 예기치 않게 오프라인이 되면 `sail host status`로 네트워크와 서비스를 확인합니다. 기본 오프라인 판정 시간은 90초입니다. 10분 동안 오프라인이면 알림이 표시되고 다시 연결되면 사라집니다.
- 업데이트에 실패하면 머신 항목을 열어 이유를 확인하고 `sail`을 설치한 사용자로 표시된 복구 명령을 실행합니다. 로컬 백업을 사용할 수 없다면 페어링 페이지의 설치 명령을 사용합니다.
- 머신이 서버 식별 정보가 바뀌었다고 보고하면 연결을 거부합니다. 머신에서 `sail host status --trust`를 실행해 저장된 지문을 확인합니다. 예상한 변경이라면 `sail login`을 실행하고 터미널에서 새 지문을 확인한 뒤 새 페어링을 승인합니다.
- `sail login`에서 `origin_mismatch`가 표시되면 주소를 바꾸기 전에 위 제거 절차를 따릅니다. 그런 다음 연결할 앱의 **머신** 페이지에서 설치 명령을 복사합니다. 로컬 페어링 인증 정보를 읽을 수 없는 경우에도 제거 후 다시 페어링해야 합니다.
- `sail uninstall`이 서비스에서 사용 중단을 확인할 수 없었다고 보고해도 로컬 파일은 제거된 상태입니다. **머신**을 열고 해당 항목을 제거합니다.
