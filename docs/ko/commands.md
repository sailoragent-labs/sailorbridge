# 명령

팀 채팅에서 **리더**에게 요청하거나 플로를 시작할 수 있습니다. 터미널에서 `sail`을 사용해 설치된 머신을 관리하거나, 팀 작업을 확인하거나, 같은 팀의 다른 머신에서 명령을 실행할 수 있습니다.

## 팀 채팅에서 명령 고르기

팀의 **채팅**을 열고 `/`를 입력합니다. 메뉴에는 바로가기 4개와 팀에서 활성화한 플로가 표시되고 맨 아래에 `/clear`가 나옵니다. 항목을 선택한 뒤 원하는 언어로 요청을 덧붙여 보냅니다. 명령 이름은 영어를 유지합니다. `/clear`를 선택하면 즉시 적용됩니다.

| 입력할 내용 | 결과 |
| --- | --- |
| `/job #12 What is this waiting for?` | **리더**에게 작업 12와 질문을 전달합니다. |
| `/event #6 Move this to weekdays.` | **리더**에게 예약 이벤트 6과 변경 요청을 전달합니다. |
| `/memory #3 When does this apply?` | **리더**에게 메모리 항목 3과 질문을 전달합니다. |
| `/do Check the current branch.` | **리더**가 이번 채팅 차례에 작업하고, 완료하지 못한 사항을 포함해 결과를 보고합니다. |
| `/clear` | 팀 채팅의 이전 메시지를 숨기고 새 대화를 시작합니다. |

해당 팀의 목록에 있는 번호를 사용합니다. 작업, 이벤트, 메모리는 각각 번호를 사용합니다. 상세 페이지에서 **채팅으로 이동**을 선택하면 해당 바로가기와 번호가 입력됩니다. 머신을 이름으로 지정하려면 `@`를 입력하고 팀 목록에서 선택합니다.

## 이름으로 플로 실행하기

| 명령 | 결과 |
| --- | --- |
| `/ask` | 질문을 하나씩 받고 나면 채팅에 요구 사항 요약이 표시됩니다. |
| `/plan` | 계획을 세우는 작업입니다. 계획을 읽고 제안된 작업을 대기열에 넣을지 결정합니다. |
| `/agent` | 워커 한 명이 작업을 수행하고 결과를 보고합니다. |
| `/write-review` | 작성자가 작업하고 검사를 실행한 뒤 플로의 검토 설정에 따라 수정합니다. |
| `/memory-tidy` | 팀 메모리 항목을 확인하고 병합하거나 제거하는 작업입니다. |
| `/docs-tidy` | 프로젝트 문서를 확인하고 판단이 필요한 문제를 보고하는 작업입니다. |
| `/code-sweep` | 읽기 전용으로 점검하고, 선택해서 실행할 수 있는 정리 작업에 번호를 붙여 보여 줍니다. |
| `/write-flow` | 반복할 작업을 설명합니다. 작업에 성공하면 새 플로가 이 팀에 저장됩니다. |
| `/edit-flow` | 플로 이름과 변경할 내용을 입력합니다. 수정에 성공하면 사용자 지정 플로가 교체됩니다. 기본 제공 플로를 수정하면 새 이름으로 사용자 지정 플로가 만들어집니다. |

예를 들어 `/agent Count the top-level files in this project.`를 보냅니다. 백그라운드 플로를 직접 보내면 작업 실행을 승인한 것으로 처리됩니다. **리더**가 대화를 바탕으로 작업 내용을 작성합니다. **바로 시작**이 켜져 있으면 입력한 내용이 바로 대기열에 들어갑니다. 채팅의 작업 행에서 **자세히 보기**를 열어 진행 상황을 확인합니다. **리더**가 일반 채팅에 대한 응답으로 백그라운드 플로를 제안하면 카드를 읽고 **네, 진행**을 선택해 시작합니다. [플로 및 예약 이벤트](flows-and-scheduled-events.md)

## 머신 페어링, 확인 또는 제거하기

| 터미널 명령 | 사용 방법 |
| --- | --- |
| `sail login` | 설치 명령이 이 명령을 실행합니다. 새 페어링 코드를 받거나 기존 인증 정보로 같은 주소의 서비스를 복구하려면 다시 실행합니다. |
| `sail host status` | 페어링, 연결, 서비스, 버전 및 로그 위치를 확인합니다. 저장된 서버 키 지문을 보려면 `--trust`를 추가합니다. |
| `sail --version` | 설치된 버전을 표시합니다. |
| `sail upgrade` | 지금 업데이트를 확인합니다. 새 버전을 설치했는지, 이미 최신인지, 업데이트에 실패했는지 표시합니다. |
| `sail host service status` | 백그라운드 서비스를 확인합니다. 설치하려면 `sail host service install`, 다시 시작하려면 `sail host service restart`, 중지하려면 `sail host service stop`를 실행합니다. |
| `sail host run` | 다른 인스턴스가 실행 중이지 않을 때 머신 서비스를 포그라운드에서 실행합니다. |
| `sail confirm` | **본인 확인** 화면에서 쓸 일회용 로그인 코드를 페어링된 머신의 터미널에서 받습니다. |
| `sail recover` | **비밀번호를 잊으셨나요?** 화면에서 쓸 선장 ID와 일회용 비밀번호 복구 코드를 페어링된 머신의 터미널에서 받습니다. |
| `sail uninstall` | SailorBridge와 작업용 복사본, 로그를 포함한 로컬 데이터를 제거합니다. 직접 만든 프로젝트 디렉터리와 엔진 로그인은 유지됩니다. |

엔진 로그인의 경우 `sail account list`로 이 머신이 인식한 로그인을 확인합니다. `sail account add <name> <directory>`로 로그인 디렉터리를 등록하고, `sail account remove <name>`로 등록을 제거하거나 기본 로그인을 무시할 수 있으며, `sail account restore <provider>`로 무시했던 기본 로그인을 다시 인식하도록 할 수 있습니다. 호환 엔드포인트용 `sail account create <provider>`는 `~/.sailorbridge/` 아래에 설정 템플릿을 작성합니다. `sail uninstall`을 실행하면 이 디렉터리가 삭제됩니다. [템플릿으로 GLM, DeepSeek 또는 Kimi 계정 설정](engine-accounts-and-pacing.md#템플릿으로-glm-deepseek-또는-kimi-계정-설정)

## 번호가 붙은 팀 항목 다루기

페어링된 머신의 터미널에서 팀에 설정된 프로젝트 디렉터리로 이동하여 다음 명령을 실행합니다. 해당 팀의 항목 번호를 사용합니다. 예를 들어 채팅에서 `#12`로 표시되는 작업은 터미널 명령에서 `12`로 입력합니다.

| 할 일 | 터미널에서 실행할 수 있는 명령 |
| --- | --- |
| 작업 찾기 | `sail job list`는 열린 작업을 나열합니다. 종료된 작업을 포함하려면 `--all`을 추가합니다. `sail job get 12`는 작업 12를 표시합니다. 전체 세부 정보를 보려면 `--json`을 추가합니다. |
| 작업 중지 또는 삭제 | `sail job stop 12`은 작업을 중지합니다. `sail job delete 12`는 종료된 작업 기록을 삭제합니다. |
| 이벤트 찾기 | `sail event list`는 앞으로 실행될 활성 이벤트를 나열합니다. 비활성화되었거나 완료된 이벤트를 포함하려면 `--all`을 추가합니다. `sail event get 6`은 메시지와 일정을 표시합니다. |
| 이벤트 삭제 | `sail event delete 6`는 예약 이벤트를 제거합니다. |
| 메모리 삭제 | `sail memory delete 3`은 항목을 영구 삭제합니다. 잠긴 항목을 삭제하려면 앱에서 **팀 메모리**를 사용합니다. |

아래 명령을 실행하려면 활성 **리더** 세션 또는 작업이 필요합니다. 팀 디렉터리에서도 터미널에서 직접 실행하면 `local_team_context_missing`가 반환됩니다. 팀 채팅에서 **리더**에게 요청합니다. 기존 항목을 직접 다루려면 앱에서 **작업 목록**, **예약 이벤트** 또는 **팀 메모리**를 엽니다. 워커는 작업과 이벤트를 읽을 수만 있습니다.

| 실행 주체 | 할 일과 명령 |
| --- | --- |
| **리더** | `sail job create <flow> "<task>"`는 백그라운드 플로를 대기열에 넣습니다. `sail job edit 12 "<revised task>"`는 열린 작업을 변경합니다. `sail job retry 12`는 이어서 실행할 수 있는 작업을 같은 번호로 계속합니다. |
| **리더** | `sail event create "Check the queue" --weekdays 09:00`는 머신의 시간대를 기준으로 팀 채팅에 메시지를 예약합니다. 다른 일정에는 `--once`, `--daily` 또는 `--every`를 사용합니다. 시간대는 `--tz`로 지정합니다. `sail event edit 6 --disable`는 이벤트를 일시 중지합니다. |
| **리더** 또는 워커 | `sail memory list`는 항목을 나열합니다. `sail memory titles`는 제목을 나열합니다. `sail memory search "release checklist"`는 일치하는 결과를 최대 10개 반환합니다. `sail memory get 3`은 항목을 읽습니다. |
| **리더** 또는 워커 | `sail memory create "<title>" "<body>"`는 사실을 기록하거나 같은 제목으로 수정 사항을 제출합니다. `sail memory edit 3 "<body>"`는 항목을 변경합니다. `sail memory conflicts`는 해결되지 않은 충돌을 나열합니다. |
| **리더** | `sail memory resolve <id> --value "<correct text>"`는 충돌을 해결합니다. 인수로 충돌 ID를 받습니다. 잠긴 항목은 **팀 메모리**에서 직접 결정해야 합니다. |
| **리더** 또는 워커 | `sail memory list --tidy`는 후보 항목과 버전을 나열합니다. `sail memory review 3 --rev <version>`는 보관할 가치가 있는 항목을 표시합니다. `sail memory merge`는 여러 개의 `--entry <id>:<version>` 인수와 `--title` 및 `--body`를 받습니다. 워커가 수행하는 작업 중 항목을 삭제할 수 있는 플로는 `/memory-tidy`뿐입니다. |

명령이 결정 대기 중이라고 보고하면 변경이 적용됐다고 판단하기 전에 응답에 있는 현재 값을 확인합니다.

## 로컬 또는 다른 팀 머신에서 명령 실행하기

로컬에서 `sail run git status`를 실행하면 출력이 터미널로 돌아옵니다. 입력 없이 오래 실행되는 명령이라면 명령 앞에 `--fold`를 추가합니다. 결과, 출력의 마지막 몇 줄 및 전체 로그 경로를 받습니다. 로컬 tmux 창의 텍스트는 `sail tmux read <window>`로 확인합니다. `sail tmux send <window> "<text>"`는 입력란을 채웁니다. 입력을 제출하려면 `sail tmux send <window> --key Enter`를 보냅니다.

같은 팀에 속한 내 다른 머신에서 명령을 실행하려면 팀 디렉터리에서 시작하고 `build-machine`을 대상 머신 이름으로 바꿉니다. 예를 들어 `sail exec build-machine git status --short`는 대상 머신의 해당 팀 디렉터리에서 실행됩니다. 종료 코드와 합쳐진 출력의 마지막 40줄이 최대 16 KiB까지 터미널로 돌아옵니다. 결과를 하나의 JSON으로 받으려면 머신 이름 앞에 `--json`을 붙입니다.

기본 제한 시간은 5분입니다. 변경하려면 머신 이름 앞에 `--timeout`과 양수로 된 초 단위 시간 값을 넣습니다. 보내는 머신 한 대에는 결과를 기다리는 명령이 최대 8개까지 있을 수 있습니다. Ctrl-C를 누르면 터미널에서 대기를 멈춥니다. 원격 명령은 계속 실행 중일 수 있습니다.

## 문제가 생겼을 때

- 채팅에서 명령을 알 수 없다고 나오면 `/`를 입력하고 활성화된 플로를 선택합니다. 이전 확인 카드가 비활성화된 플로를 가리키면 **팀 플로**에서 플로를 활성화하거나 사용 가능한 플로를 선택해 요청을 다시 보냅니다.
- 번호가 붙은 바로가기의 항목을 찾을 수 없으면 이 팀의 **작업 목록**, **예약 이벤트** 또는 **팀 메모리**를 엽니다. 번호를 확인한 뒤 채팅에서 `#`을 붙입니다.
- `sail exec`가 팀을 식별하지 못하면 목록에 나온 팀 디렉터리 중 하나로 이동합니다. 대상 머신이 오프라인이거나 작업 접수를 멈췄다면 온라인으로 돌아와 작업을 받을 때 다시 시도합니다. 온라인 대상이 대기 중인 명령을 가져갈 때까지 최대 10분 동안 기다립니다. 명령을 가져가기 전에 오프라인이 되면 재연결을 60초 동안 기다립니다. 실행을 시작한 뒤 대상과 연결이 끊기면 다시 실행하기 전에 명령이 한 일을 확인합니다.
