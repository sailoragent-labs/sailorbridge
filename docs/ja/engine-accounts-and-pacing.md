# エンジンアカウントと実行ペース

Agent は自分のマシンでログインしたエンジンアカウントを使います。チームが使えるアカウント、利用枠の残り、作業が再開する時刻を確認できます。SailorBridge のプランで同時実行できる Agent 数が決まります。使えるモデルと利用枠はエンジンの提供元が決めます。

## アカウントを探す、または追加する

1. 実行したいマシンで Claude Code または Codex にログインします。`sail account list` を実行します。既定のログインは自動で検出されます。通常、名前はエンジン名に `@` とマシン名をつないだものです。
2. 別のログインを追加するには、別のアカウントディレクトリでエンジンにログインします。`sail account add <name> <directory>` に、そのディレクトリと、そのマシン内で重複せず、空白やスラッシュを含まない 1～64 文字の名前を指定します。たとえば 2 つ目のログインが該当する場所にあるなら、`sail account add work "$HOME/codex-work"` を実行します。再起動しなくても、次回の利用枠の読み取りで認識されます。
3. **リソース** から **アカウント** を開きます。アカウントを選ぶと、マシン、利用枠、利用可能なモデルを確認できます。複数のマシンで同じエンジンが同名で報告したアカウントは、1 行にまとまります。ログインディレクトリ、メールアドレス、認証情報はマシンに残ります。

Codex はサブスクリプションでのログインに対応しています。Claude Code はサブスクリプションでのログインまたは API キーに対応しています。Gemini CLI、Copilot CLI、OpenCode、Qwen Code、Pi は、アカウントの登録とローカルでの確認のみ可能です。この 5 つでは、Gemini CLI と OpenCode が別の名前付きディレクトリに対応しています。

## Claude 互換のエンドポイントを使う

DeepSeek や GLM などを使う場合は、自分のマシンに Claude Code 用の別のアカウントディレクトリを設定します。その `settings.json` で、提供元のベース URL を `env.ANTHROPIC_BASE_URL` に、認証情報を `env.ANTHROPIC_API_KEY` または `env.ANTHROPIC_AUTH_TOKEN` に設定します。同じ `env` オブジェクト内の `ANTHROPIC_MODEL` に、提供元のモデル名を設定します。`ANTHROPIC_DEFAULT_OPUS_MODEL`、`ANTHROPIC_DEFAULT_SONNET_MODEL`、`ANTHROPIC_DEFAULT_HAIKU_MODEL` で Opus、Sonnet、Haiku の各モデル系列を個別に対応付けられます。

そのマシンで、選んだ名前とパスを指定して `sail account add <name> <directory>` を実行します。アカウントは Claude Code 経由で動作します。**利用可能なモデル** を開くと、ディレクトリから読み取ったモデル名が表示されます。エンドポイントのモデルにはこの対応付けが使われ、推論の強度は設定できません。実際に使われたモデルは作業の詳細に表示されます。

## テンプレートで GLM、DeepSeek、Kimi のアカウントを設定する

`sail account create` は、提供元のエンドポイント、上位・中位・下位の推奨モデル、キーのプレースホルダーを含む Claude Code のローカル設定ファイルを書き込みます。キーの入力を求めたり、読み取ったり、送ったりすることはなく、アカウントの登録も行いません。

GLM を設定するには、アカウントを使うマシンで次を実行します。

```sh
sail account create glm
```

コマンドは 3 行を表示します。ここで `~` はホームディレクトリを表します。

```text
推奨モデル（Opus/Fable、Sonnet、Haiku/サブエージェント）：glm-5.3、glm-5.2、glm-5.3-flash。
モデル ID は3種類です。Sonnet には中間層として提案されたモデルを割り当てます。
~/.sailorbridge/account-templates/glm/settings.json のプレースホルダーを自分の API キーに置き換え、sail account add <name> ~/.sailorbridge/account-templates/glm を実行してください。
```

生成された `settings.json` には、次のテンプレートが入っています。

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "REPLACE_WITH_YOUR_API_KEY",
    "ANTHROPIC_BASE_URL": "https://api.z.ai/api/anthropic",
    "ANTHROPIC_MODEL": "glm-5.3",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "glm-5.3",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "glm-5.2",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "glm-5.3-flash",
    "ANTHROPIC_DEFAULT_FABLE_MODEL": "glm-5.3",
    "CLAUDE_CODE_SUBAGENT_MODEL": "glm-5.3-flash"
  }
}
```

`nano` などのテキストエディターでファイルを開きます。

```sh
nano ~/.sailorbridge/account-templates/glm/settings.json
```

`REPLACE_WITH_YOUR_API_KEY` を自分の GLM キーに置き換え、引用符は残して保存します。選んだ名前でディレクトリを登録します。この例では `glm` を使います。名前はマシン内で重複せず、1～64 文字で、空白文字や `/` を含められません。

```sh
sail account add glm ~/.sailorbridge/account-templates/glm
sail account list
```

ターミナルの一覧で `glm` を探します。マシンからアカウントが報告されたら、アプリで **リソース** から **アカウント** を開きます。`glm` を選んで **利用可能なモデル** を確認します。

DeepSeek または Kimi の場合は、各提供元に対応するコマンドから始めます。出力されたパスの `settings.json` を開き、プレースホルダーを提供元のキーに置き換えます。表示された `sail account add` に選んだ名前を指定して実行し、`sail account list` で確認します。

| テンプレート作成コマンド | ファイル内のエンドポイント | 表示される推奨モデル |
| --- | --- | --- |
| `sail account create deepseek` | `https://api.deepseek.com/anthropic` | 上位は `deepseek-v4-pro`、中位と下位は共通で `deepseek-flash` を使います。 |
| `sail account create kimi` | `https://api.kimi.com/coding/` | Kimi Coding Plan のキーを使います。3 段階とも `k3.1-pro[1m]` を使います。 |

MiniMax には `--region international` または `--region china` の指定が必要です。GLM、DeepSeek、Kimi は `--region` を受け付けません。

## 利用枠を確認し、自分用に残す

**アカウント** でアカウントを開き、**利用枠**、**リセット**、**計測** を合わせて確認します。サブスクリプションの読み取り結果には、5 時間の利用枠、週ごとの利用枠、特定モデルの週ごとの利用枠が表示される場合があります。Codex は標準の週間枠を報告します。利用枠の読み取りにモデルトークンは使いません。新しい読み取りに失敗しても、1 時間以内の成功結果が古い情報として表示されることがあります。読み取り結果がない場合は理由が示され、そのアカウントを作業に使えることもあります。

- **使用を許可** は、自分の全チームでこのアカウントに新しい作業を割り当てるかを制御します。オフにしても実行中の作業は完了できます。
- **予約ライン** は、自分用に一定割合を残す設定です。0% から 100% まで 5 ポイント刻みで設定できます。1 日より長い期間の利用枠で、残りがその割合以下になると、ワーカーと **リーダー** はアカウントの使用を止めます。短い期間の枠はすべて使えます。
- 支出で計測するアカウントでは、**月間上限** にマシンが暦月内に使ってよい最大額を設定します。たとえば DeepSeek に適用されます。GLM は独自の利用枠を報告します。上限に達すると、上限を引き上げない限り、新しい作業は翌月 1 日の午前 0 時（UTC）まで待ちます。進行中のステップは上限を超えても完了できます。同じアカウントを複数のマシンに登録すると、各マシンが個別に支出を計測します。**費用算出不可** と表示された場合はトークン数を確認できますが、上限は適用されません。
- Claude または Codex から報告されると、**リセット券** が表示されます。リセット券を開き、リセット対象と期限を確認してから **使う** を選んで確定します。アカウント一覧の **リセットを使う** を選ぶと、対象のうち期限が最も近いリセット券が使われます。アカウントのあるマシンがリセットを行います。別のリセット券を使う前に結果を確認します。

## チームごとにアカウントとモデルを選ぶ

チームチャットのメニューから **アカウント一覧** を開きます。既定でチームのマシン上のアカウントが含まれます。**役割** で **両方**、**書くだけ**、**レビューだけ** のいずれかを選び、そのアカウントを使えるワーカーのステップを指定します。**リーダー専用** でこのチームのチャット専用にします。**チームから外す** と **チームにアカウントを追加** で、このチームで使えるかどうかを変更します。

**チームの詳細** から割り当て設定を開きます。**リーダーモデル** で、チームのマシン上の有効なアカウントを選び、検出されたモデルと、設定できる場合は推論の強度を選びます。別のマシン上のアカウントを選ぶと、次のメッセージから **リーダー** がそのマシンに移ります。選んだアカウントを実行できない場合は、代わりに使用したエンジンとモデルが返信に表示されます。

ワーカー用には、チームのモデル設定で、難易度とエンジンごとに優先するモデルと推論の強度を設定します。フローの書き手とレビュー担当のオプションでエンジンを選びます。自動レビューでは、できる限り書き手が実際に使ったモデル系列を避けます。フローが指定したエンジンをその役割に使えるアカウントがチームにない場合は、その実行に限って自動選択を使うことがあります。変更の理由は作業の詳細に表示されます。

作業には、すべてのステップを実行できる 1 台のマシンが必要です。そのマシン上で、各ステップはエンジンと役割に対応する有効なアカウントを使います。対象の中では、ログイン更新待ちのアカウントが優先されます。次に、1 日以内にリセットされるアカウントが、リセットの早い順に選ばれます。それより後の場合は、使える利用枠、プランの容量、リセットまでの時間を考慮します。読み取り結果のないアカウントは最後です。差分レビューや変更が 120 行以下の初回レビューでは、余裕のある小さいプランが優先されます。

## 新しい作業のペースを設定する

**リソース** から **速度制限方式** を開きます。既定の **利用枠に合わせる** は、利用枠の期間全体に作業を分散します。使用済みの割合が経過時間の割合を 100/7 ポイント（約 14.3 ポイント）より多く上回り、かつ期間の残りが 7 分の 1 を超えていると、アカウントは使用ペースが速すぎる状態です。利用できるアカウントがすべてその状態なら、マシンは新しい作業を引き受ける前に待機します。実行中の作業と **リーダー** とのチャットは続行できます。

**制限なし** を選ぶと、全チームがペースの上限で待たずに新しい作業を引き受けます。アカウントの予約枠と使い切った利用枠は引き続き適用されます。いずれかのチームで **リーダー** に選ばれたアカウントで、アカウント全体の枠の残りが 10% 未満になると、ワーカーはそのアカウントをチャットのために残します。同じページで **利用枠に合わせる** に戻せます。

## うまくいかないとき

- テンプレートファイルがすでにある場合、コマンドは上書きせず、パスを表示します。そのファイルを編集し、格納先のディレクトリを登録します。
- コマンドがディレクトリを拒否したら、表示されたパスを確認します。自分だけがアクセスできるように、ディレクトリは自分のユーザーが所有し、権限は `0700` である必要があります。所有者と権限を修正してからテンプレート作成コマンドを再実行します。
- `sail uninstall` は、これらの設定ファイルを含む `~/.sailorbridge/` を削除します。キーのコピーは別の場所にも保管します。
- 登録に失敗したら、指定したディレクトリについてターミナルに表示されるログインコマンドに従います。ディレクトリで認識されるエンジンは 1 つである必要があります。`sail account list` で名前を確認します。登録の削除や既定のログインを無視するには `sail account remove <name>` を実行します。ローカルの認証情報は残ります。既定のログインを再び認識させるには `sail account restore claude` または `sail account restore codex` を実行するか、マシンの **無視しているログイン** を開いて **復元** を選びます。
- **ログイン期限切れ** の場合は、表示されたマシンで再びログインします。**ログイン更新待ち** の場合は、マシンが更新を試みます。**ネットワーク接続不可** の場合は、そのマシンの接続を確認します。提供元のレート制限や一時的な停止の場合は、時間を置いて再試行されます。モデル選択欄でアカウントが **モデル未取得** と表示されたら、読み取りを待つか、モデルが検出済みのアカウントを選びます。
- チームが **リーダー** 用のアカウントの削除を拒否したら、まず **リーダーモデル** で別のアカウントを選びます。書き手またはレビュー担当が不足している作業では、詳細の **アカウントへ** を選び、すべてのステップを実行できるマシンで不足する役割を有効にします。
- **作業一覧** を開いて **実行されていない理由** を読みます。ペースによる待機には見込み時刻が表示されます。そのまま待つか、全チームの **制限なしに切り替え** を確定できます。使えるアカウントの利用枠を使い切った作業は、同じマシンで待機して表示時刻に再確認します。ログインするか利用枠が戻ると、自動で再開します。
