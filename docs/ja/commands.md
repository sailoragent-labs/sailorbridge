# コマンド

チームチャットでは、**リーダー** に依頼したり、フローを開始したりできます。ターミナルでは `sail` を使って、インストール先のマシンを管理し、チームの作業を確認し、同じチームの別のマシンでコマンドを実行できます。

## チームチャットでコマンドを選ぶ

チームの **チャット** を開き、`/` と入力します。メニューには 4 つのショートカット、チームで有効なフロー、最後に `/clear` が並びます。項目を選び、自分の言語で依頼内容を付け加えて送ります。コマンド名は英語のままです。`/clear` を選ぶとすぐに反映されます。

| 入力する内容 | 結果 |
| --- | --- |
| `/job #12 What is this waiting for?` | **リーダー** に作業 12 と質問が渡ります。 |
| `/event #6 Move this to weekdays.` | **リーダー** に定時イベント 6 と変更の依頼が渡ります。 |
| `/memory #3 When does this apply?` | **リーダー** にチームメモリの項目 3 と質問が渡ります。 |
| `/do Check the current branch.` | **リーダー** がこのチャットのターンで作業し、できなかったことも含めて結果を報告します。 |
| `/clear` | チームチャットで以前のメッセージが非表示になり、新しい会話が始まります。 |

該当するチームの一覧にある番号を使います。作業、イベント、記憶にはそれぞれ番号があります。詳細画面の **チャットへ** を選ぶと、対応するショートカットと番号が入力されます。マシンを名前で指定するには、`@` と入力してチームの一覧から選びます。

## フローを名前で実行する

| コマンド | 結果 |
| --- | --- |
| `/ask` | 質問が 1 つずつ出され、最後にチャットで要件の概要が示されます。 |
| `/plan` | 計画を立てる作業です。計画を読んで、提案されたタスクをキューに入れるか決めます。 |
| `/agent` | 1 人のワーカーが作業し、結果を報告します。 |
| `/write-review` | 書き手が作業し、チェックを実行して、フローのレビュー設定に従って修正します。 |
| `/memory-tidy` | チームメモリを確認し、項目を統合または削除する作業です。 |
| `/docs-tidy` | プロジェクトの文書を確認し、判断が必要な問題を報告する作業です。 |
| `/code-sweep` | 読み取り専用で点検し、実行するか選べる整理タスクを番号付きで示します。 |
| `/write-flow` | 繰り返し行う作業を説明します。作業が成功すると、新しいフローがこのチームに保存されます。 |
| `/edit-flow` | フロー名と変更内容を指定します。編集が成功するとカスタムフローが置き換わります。組み込みのフローを編集すると、新しい名前のカスタムフローが作成されます。 |

たとえば `/agent Count the top-level files in this project.` と送ります。バックグラウンドのフローを自分で送ると、作業の実行が承認されます。**リーダー** が会話をもとに作業内容をまとめます。**直接開始** がオンの場合は、入力した言葉がそのままキューに入ります。チャットの作業欄で **詳細を見る** を開き、進捗を追います。通常のチャットに応じて **リーダー** がバックグラウンドのフローを提案した場合は、カードを読み、**はい、実行** を選んで開始します。[フローと定時イベント](flows-and-scheduled-events.md)

## 保護された操作に使う署名付きの指示

SailorBridge は、チームに送るメッセージに自動で署名します。これには `/agent` などのフローコマンドや、Agent セッションで自分のチームに送る非公開の指示が含まれます。カードでの回答や作業・コマンドの承認、定時イベントに保存した指示にも署名します。作業の **やり直す** や **続行** が利用できる場合、その操作にも署名します。

`sail exec` でチーム内の別のマシンにコマンドを送る場合は、送信元のペアリング済みマシンが署名します。友だちとの会話は通常のチャットです。転送されたメッセージやエージェントの返信は作業の参考にできます。

保護された指示を使う前に、受信側のマシンは、そのアカウントで承認されたデバイスから届いた指示か、対象のチームと操作に対応しているかを確認します。コマンドの承認では、該当するカード、コマンド、実行先も確認します。必要な署名がない場合や、期限切れの場合、新しい承認と矛盾する場合、操作と一致しない場合は、マシンがその操作を拒否します。あなたが送ったと確認できないチームメッセージで作業を承認することはできません。

**セキュリティ** の **最近のセキュリティ記録** で、**マシンがコンテンツを検証できませんでした** という通知と影響を受けた作業を確認できます。拒否された指示は内容を見直して送り直すか、作業を再度開始します。回答が使われなかった場合は、カードを更新してもう一度回答します。コマンドの承認が拒否された場合は、内容を見直し、最新のカードで再度承認します。定時イベントが実行されなかった場合は、見直して保存し直します。`sail exec` で検証に失敗したと表示された場合、リモートコマンドは実行されていません。

**このデバイスを準備しています** と表示されたら、アプリを開いたままにして、以前使ったことのある、作業を承認できるデバイスをオンラインにします。アプリは準備中に操作を保留し、操作がまだ有効だと確認できた時点で送信します。

## マシンをペアリング、確認、削除する

| ターミナルのコマンド | 使い方 |
| --- | --- |
| `sail login` | インストールコマンドが自動で実行します。新しいペアリングコードを取得するときや、既存の認証情報で同じアドレスのサービスを復旧するときに再実行します。 |
| `sail host status` | ペアリング、接続、サービス、バージョン、ログの場所を確認します。`--trust` を付けると、保存されたサーバー鍵のフィンガープリントが表示されます。 |
| `sail --version` | インストール済みのバージョンを表示します。 |
| `sail upgrade` | 更新をすぐに確認します。新しいバージョンをインストールしたか、すでに最新版か、更新に失敗したかが表示されます。 |
| `sail host service status` | バックグラウンドサービスを確認します。インストールは `sail host service install`、再起動は `sail host service restart`、停止は `sail host service stop` を使います。 |
| `sail host run` | 別のインスタンスが動作していないときに、マシンのサービスをフォアグラウンドで実行します。 |
| `sail confirm` | **本人確認** で使う 1 回限りのログインコードを、ペアリング済みマシンのターミナルで取得します。 |
| `sail recover` | **パスワードをお忘れですか?** で使う船長 ID と 1 回限りのパスワード復旧コードを、ペアリング済みマシンのターミナルで取得します。 |
| `sail uninstall` | SailorBridge とローカルデータを削除します。作業用コピーとログも削除されます。自分のプロジェクトディレクトリとエンジンのログインは保持されます。 |

エンジンへのログインのうち、このマシンが認識しているものは `sail account list` で確認できます。`sail account add <name> <directory>` でログイン先のディレクトリを登録し、`sail account remove <name>` で登録を削除するか既定のログインを無視できます。無視した既定のログインを再び認識させるには `sail account restore <provider>` を使います。互換エンドポイント向けの `sail account create <provider>` は `~/.sailorbridge/` に設定テンプレートを書き込みます。このディレクトリは `sail uninstall` で削除されます。[テンプレートで GLM、DeepSeek、Kimi のアカウントを設定する](engine-accounts-and-pacing.md#テンプレートで-glmdeepseekkimi-のアカウントを設定する)

## 番号付きのチーム項目を操作する

ペアリング済みマシンのターミナルで、チームに設定されたプロジェクトディレクトリに移動してから、次のコマンドを実行します。自分のチームの項目番号を使います。たとえばチャットで `#12` と表示された作業は、ターミナルのコマンドでは `12` と指定します。

| 操作 | ターミナルで実行できるコマンド |
| --- | --- |
| 作業を探す | `sail job list` で未終了の作業を一覧表示します。終了済みの作業も含めるには `--all` を追加します。`sail job get 12` で作業 12 を表示します。詳細をすべて出すには `--json` を追加します。 |
| 作業を停止または削除する | `sail job stop 12` で作業を停止します。`sail job delete 12` で終了済みの作業の記録を削除します。 |
| イベントを探す | `sail event list` で実行予定のある有効なイベントを一覧表示します。無効または完了済みのイベントも含めるには `--all` を追加します。`sail event get 6` でメッセージとスケジュールを表示します。 |
| イベントを削除する | `sail event delete 6` で定時イベントを削除します。 |
| 記憶を削除する | `sail memory delete 3` で項目を完全に削除します。ロックされた項目を削除するには、アプリの **チームメモリ** を使います。 |

以下のコマンドには、進行中の **リーダー** セッションまたは作業が必要です。チームのディレクトリであっても、ターミナルから直接実行すると `local_team_context_missing` が返ります。チームチャットで **リーダー** に依頼します。既存の項目を自分で操作するには、アプリで **作業一覧**、**定時イベント**、または **チームメモリ** を開きます。ワーカーによる作業とイベントへのアクセスは読み取り専用です。

| 実行する人 | 操作とコマンド |
| --- | --- |
| **リーダー** | `sail job create <flow> "<task>"` でバックグラウンドのフローをキューに入れます。`sail job edit 12 "<revised task>"` で未終了の作業を変更します。`sail job retry 12` で再開できる作業を同じ番号で続けます。 |
| **リーダー** | `sail event create "Check the queue" --weekdays 09:00` でマシンのタイムゾーンに合わせてチームチャットへのメッセージを予約します。ほかのスケジュールでは `--once`、`--daily`、または `--every` を使います。タイムゾーンを指定するには `--tz` を使います。`sail event edit 6 --disable` でイベントを一時停止します。 |
| **リーダー** またはワーカー | `sail memory list` で項目、`sail memory titles` でタイトルを一覧表示します。`sail memory search "release checklist"` は最大 10 件の一致を返します。`sail memory get 3` で項目を読みます。 |
| **リーダー** またはワーカー | `sail memory create "<title>" "<body>"` で事実を記録し、または同じタイトルの項目への訂正を出します。`sail memory edit 3 "<body>"` で項目を変更します。`sail memory conflicts` で未解決の競合を一覧表示します。 |
| **リーダー** | `sail memory resolve <id> --value "<correct text>"` で競合を解決します。指定するのは競合 ID です。ロックされた項目は **チームメモリ** で自分で判断します。 |
| **リーダー** またはワーカー | `sail memory list --tidy` で候補とバージョンを一覧表示します。`sail memory review 3 --rev <version>` で残すべき項目に印を付けます。`sail memory merge` には `--entry <id>:<version>` を繰り返し指定し、さらに `--title` と `--body` を指定します。ワーカーが実行する作業で項目を削除できるのは `/memory-tidy` だけです。 |

コマンドが判断待ちを報告したら、変更が反映されたと考える前に、応答に含まれる現在の値を確認します。

## ローカルまたはチームの別のマシンでコマンドを実行する

ローカルでは `sail run git status` の出力がターミナルに返ります。対話を必要としない長時間のコマンドには、コマンドの前に `--fold` を追加します。結果、出力の末尾数行、完全なログのパスが返ります。ローカルの tmux ウィンドウでは、`sail tmux read <window>` で表示内容を読み取れます。`sail tmux send <window> "<text>"` は入力欄を埋めます。入力を確定するには `sail tmux send <window> --key Enter` を送ります。

同じチームにある自分の別のマシンでコマンドを実行するには、チームのディレクトリから実行し、`build-machine` を対象のマシン名に置き換えます。たとえば `sail exec build-machine git status --short` は対象マシンのチームディレクトリで実行されます。終了コードと、結合した出力の末尾 40 行まで、最大 16 KiB がターミナルに返ります。1 つの JSON 結果を得るには、マシン名の前に `--json` を付けます。

既定の制限時間は 5 分です。変更するには、マシン名の前に `--timeout` と正の秒数を指定します。送信元のマシン 1 台につき、結果を待つコマンドは最大 8 件です。Ctrl-C を押すとターミナルでの待機が終わります。リモートのコマンドは実行を続けている場合があります。

## うまくいかないとき

- チャットでコマンドが見つからない場合は、`/` と入力して有効なフローを選びます。古い確認カードが無効なフローを指している場合は、**チームのフロー** で有効にするか、利用できるフローを選んで新しい依頼を送ります。
- 番号付きのショートカットに該当する項目が見つからない場合は、そのチームの **作業一覧**、**定時イベント**、または **チームメモリ** を開きます。番号を確認し、チャットでは `#` を付けます。
- `sail exec` がチームを特定できない場合は、表示されたチームディレクトリのいずれかに移動します。対象マシンがオフラインか作業を受け付けていない場合は、オンラインになって受け付けを再開してから試します。オンラインの対象マシンが待機中のコマンドを引き受けるまで最大 10 分待ちます。引き受ける前にオフラインになると、再接続を 60 秒待ちます。開始後に接続が切れた場合は、コマンドが何を実行したか確認してから再試行します。
