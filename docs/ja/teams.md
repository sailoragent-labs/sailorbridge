# チーム

チームは、1 つのプロジェクト専用の **リーダー** とのチャット、作業キュー、チームメモリ、1 台以上のマシンを持ちます。複数のチームを持つことも、同じマシンを複数のチームで使うこともできます。チーム設定を閲覧・変更できるのは自分だけです。

## プロジェクト用のチームを作成する

1. リーダーを実行するマシンをペアリングします。**オンライン** と表示されたら、ペアリング画面で **チームを作成** を選びます。**チーム** を開いて **チーム作成** を選ぶこともできます。[マシンをペアリングする](machines.md)
2. **チーム名** を入力し、対象のマシンを選びます。**アバター** と、リーダーのアカウント、モデル、推論の強度を、そのマシンで使える選択肢から選べます。既定値のままでも構いません。
3. **プロジェクトディレクトリ** には、選んだマシン上の `/` で始まる絶対パスを入力します。すでにリポジトリで作業中なら、そのローカルディレクトリを使います。既存のリモートリポジトリを使う場合は、まずそのマシンにクローンし、Git の認証情報を設定します。SailorBridge がリポジトリのメインブランチを検出します。
4. **成果の送信先** を指定し、**チーム作成** を選びます。チームにマシンが表示されます。**チャット** を開いてリーダーと話します。[チームチャットを使う](chat.md)

チームが初めてそのパスを使うとき、既存のフォルダーを開くか、なければ作成します。ファイルの入った通常のフォルダーなら、Git を初期化して最初のスナップショットを取ります。フォルダーの直下に複数の Git リポジトリがある場合は、どのリポジトリかリーダーに伝えます。各作業は 1 つのリポジトリで行います。リポジトリをまたぐ場合は作業を分けます。

## 変更の送信先を選ぶ

**チーム** で自分のチームを開くと **チームの詳細** に移動します。そこで **プロジェクトディレクトリ** や **成果の送信先** を変更できます。変更は、マシンが次に引き受ける作業から適用されます。

| 成果の送信先 | 作業のコミットを確認する場所 |
| --- | --- |
| **自動マージ**（既定） | マシンはリモートのメインブランチへのプッシュを試みた後、ローカルのメインブランチを早送りします。リモートのメインブランチが進んでいた場合やリモート側でレビューが必須の場合は、納品レポートを確認します。作業ブランチが記載されていたら、リモートでそのブランチをマージします。 |
| **ブランチ** | 作業ごとに専用の `sb/<job>` ブランチにプッシュされ、自分で確認してマージできます。ほかの作業はプロジェクトのメインブランチから始まります。 |

各マシンは、リポジトリに設定された Git のリモートと認証情報を使います。作業を始める前にリモートのメインブランチを取得し、可能ならローカルのコピーを早送りします。プッシュに失敗した場合は、作業の **納品レポート** で理由、ローカルのブランチ、コミット、プッシュ用コマンドを確認します。[作業の納品レポートを探す](jobs.md)

## マシンを追加、移動、削除する

**チームの詳細** で **マシン一覧** を開き、プラスボタンで **マシンを追加** を選びます。ペアリング済みのマシンを選び、**チームのフォルダーと同じ** を選ぶか、**プロジェクトフォルダー** にそのマシン上の絶対パスを入力します。パスは後で編集できます。実行可能で空きがあるマシンは、同じキューから作業を引き受けられます。

マシンをチームから外すには、そのマシンを選び、**チームから外す** を確定します。そのマシンはこのキューから新しい作業を引き受けなくなります。**リーダーはこのマシンで実行** のマシンをチームから外すか利用を停止すると、残りの中で最も早く参加したマシンがリーダーを引き継ぎます。最後の 1 台はチームから外せません。先に代わりのマシンを追加します。

## チームが作業を引き受ける方法を設定する

このチームでの作業の実行方法を変更するには **チームの詳細** に戻ります。

- **ジョブ設定** の **割り当て** で新しい作業の割り当てを設定します。**停止中** を選ぶと、キュー内の作業を保留し、実行中の作業は続行します。**通常どおり** を選ぶと、マシンが再びキューから作業を引き受けられます。
- **同時に実行する作業数** の既定値は **無制限** なので、アカウントの同時実行上限が適用されます。**件数を指定** を選ぶと、このチームが同時に実行できる作業数に上限を設定できます。数を減らした場合、実行中の作業が終わるにつれて適用されます。
- **リーダーモデル** でアカウントを選び、次にモデルと、設定可能なら推論の強度を選びます。各アカウントにはマシンが表示されます。同じチームの別のマシン上のアカウントを選ぶと、次のメッセージからリーダーがそのマシンに移ります。同じ会話の要約とチームメモリを使います。実行中の作業はそれぞれのマシンに残ります。
- ワーカー用には、難易度と提供元ごとに優先するモデルと、設定可能なら推論の強度を選びます。**デフォルトに戻す** でその項目をチームの既定値に戻せます。**アカウント一覧** では、書き手、レビュー担当、リーダーのいずれがアカウントを使えるかを制限できます。[エンジンアカウントと実行ペース](engine-accounts-and-pacing.md)

## チームを解散する

**チームの詳細** を開き、**チームを解散** を選びます。終了する Agent セッションの件数を確認し、チーム名を入力して確定します。解散は取り消せません。未終了の作業が取り消され、定時イベントが削除され、チームは一覧とチャットの入口から削除されます。このチームの保留中の Agent セッションのリクエストと進行中のセッションも終了します。参加者それぞれにセッション履歴が残ります。マシンはアカウントにペアリングされたままです。

## うまくいかないとき

- 選べるマシンがなければ、チーム作成時は **マシンをペアリング**、マシン追加時は **新しいマシンをペアリング** を選びます。マシンの利用を停止していた場合は、追加前にペアリングし直します。
- 作業やチャットでディレクトリを作成できないと表示されたら、そのパスを使おうとしたマシンで確認します。そこにファイルがある、書き込み権限がない、ディスクが読み取り専用であるなどの理由で作成できない場合があります。**チーム設定でディレクトリを変更** を選び、そのマシンで書き込めるディレクトリを入力します。
- 作成中にリーダーのアカウントやモデルが使えなくなったら、更新された一覧から選び直します。作成後もキューに入れた作業が待機している場合は、作業詳細の **実行されていない理由** を読み、割り当て、上限、アカウントのどれが原因か確認します。
