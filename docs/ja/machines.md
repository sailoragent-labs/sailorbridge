# マシン

マシンは、チームのリーダーを動かしたり作業を引き受けたりするために、アカウントに接続するコンピューターです。マシンごとに `sail` をインストールし、ブラウザーで承認します。ターミナルを閉じても、バックグラウンドサービスが接続を維持します。

## インストールしてマシンをペアリングする

1. 自分で管理する Linux x64 または macOS（arm64 または x64）マシンを使います。Git をインストールします。チャットや作業を行うには、Claude Code または Codex をインストールし、そのマシンで自分のエンジンアカウントにログインします。エンジンにログインする前にペアリングを完了することもできます。
2. アプリで **マシン** から **新しいマシンをペアリング** を開きます。表示されたインストールコマンドを、接続したいマシンのターミナルにコピーします。どのディレクトリでも実行できます。`sail` がインストールされてペアリングが始まり、10 分間有効な 8 文字のコードが表示されます。
3. ブラウザーの **ペアリングコード** にコードを入力し、**ペアリング** を選びます。マシン名と **キーコード** をターミナルの表示と照合します。初回のペアリングでは、注意事項を読んでから同意します。Agent は、`sail` を実行する OS ユーザーの権限で、ファイルの読み取り、変更、削除、認証情報の使用、ネットワーク接続ができます。隔離が必要なら、専用のマシンまたはコンテナを使います。
4. **マシンの承認** を選びます。マシンが認証情報を受け取ってサービスを開始するまで、接続を維持します。**マシン** で **オンライン** と表示され、ターミナルでも接続が確認できたら、**アカウントを設定** または **チームを作成** を選べます。[チームを作成する](teams.md)

## 接続を確認し、別のマシンをペアリングする

**マシン** でマシンを開くと、名前、プラットフォーム、**最終オンライン**、**ペアリング日時**、**クライアントバージョン** を確認できます。ここで名前を変えると、どのマシンか見分けやすくなります。マシン上で `sail host status` を実行すると、ペアリング、接続、サービスの状態と、ローカルログの場所が分かります。

別のコンピューターを使うには、再び **新しいマシンをペアリング** を開き、そのコンピューターで表示されたコマンドを実行します。オンラインになったらチームに追加し、そのマシンでのプロジェクトフォルダーを設定します。1 台のマシンを複数のチームで使えます。作業はそれぞれ、チーム内の実行可能なマシン 1 台で実行されます。[チームのマシンを管理する](teams.md)

## インストールを更新または修復する

自動更新は既定でオンです。更新を検証した後、サービスは再起動し、ローカルの作業を再開します。完了したステップは保持されます。中断したローカルステップは再実行される場合があります。手動で更新するには、マシン上で `sail upgrade` を実行します。更新をインストールしたか、すでに最新版か、エラーが発生したかが表示されます。インストール済みのバージョンを確認するには `sail --version` を実行します。

サービスの復旧が必要なら、`sail login` を実行します。同じアドレスであれば、既存の認証情報を使ってサービスを再インストールし、再起動します。認証情報が拒否され、マシンが引き続き登録済みの場合は、修復のためのペアリングが始まります。ブラウザーに **既存のマシンを再ペアリング** と、置き換え対象のマシンが表示されます。詳細を確認して新しいコードを承認します。所属チームは引き継がれます。新しい認証情報を受け取った時点が、パスワード復旧で使う新しいペアリング日になります。

## マシンの利用を停止するか、アンインストールする

アカウント全体でマシンの使用をやめるには、**マシン** で該当する行のメニューを開き、**削除** を選んで確認します。認証情報が取り消され、マシンは所属チームから外れます。通知を受け取ると作業を止めます。接続中であればすぐに、それ以外は次の接続時に通知を受け取ります。ローカルの作業用コピーは保持されます。再び使うには、そのマシンで `sail login` を実行して新しいペアリングを承認し、必要とするチームに追加します。

コンピューターからアンインストールする前に、SailorBridge の作業用コピーから必要な成果を保存します。そのマシンで `sail uninstall` を実行します。サービスが停止し、`sail`、サービスの定義、インストーラーが追加したシェルのパス設定、`~/.sailorbridge/` ディレクトリ全体が削除されます。その中には認証情報、アカウントの登録、ログ、ローカルのチャット記録、作業用コピー、`sail` のバックアップが含まれます。自分のプロジェクトディレクトリとエンジンのログインディレクトリは保持されます。再インストールするには **新しいマシンをペアリング** のコマンドを使います。

## うまくいかないとき

- ペアリングで Git が見つからないと表示されたら、Git をインストールして `sail login` で続行します。エンジンが未ログインの場合は、チャットや作業を始める前に `claude login` または `codex login` で別途ログインします。
- コードの有効期限が切れたら、`sail login` で新しいものを取得します。マシン名か **キーコード** が一致しない場合は、**ペアリングをキャンセル** を選んで目的のマシンのターミナルを確認します。承認後 10 分以内にマシンが接続されない場合は、`sail host status` で状態を確認し、`sail login` を実行して再接続します。
- マシンが予期せずオフラインになった場合は、`sail host status` でネットワークとサービスを確認します。既定のオフライン判定時間は 90 秒です。オフラインの状態が 10 分続くと通知が表示され、復帰すると消えます。
- 更新に失敗したら、対象のマシンを開いて理由を確認し、`sail` をインストールしたユーザーで、表示された修復コマンドを実行します。ローカルのバックアップが使えない場合は、ペアリング画面のインストールコマンドを使います。
- サーバーの識別情報が変わったとマシンが報告した場合、接続は拒否されます。マシンで `sail host status --trust` を実行し、保存済みのフィンガープリントを確認します。想定した変更なら、`sail login` を実行してターミナルで新しいフィンガープリントを確認し、新しいペアリングを承認します。
- `sail login` に `origin_mismatch` と表示されたら、アドレスを切り替える前に上記の手順でアンインストールします。その後、接続先アプリの **マシン** 画面からインストールコマンドをコピーします。ローカルのペアリング認証情報を読み取れない場合も、アンインストールしてペアリングし直します。
- `sail uninstall` が、サービスで利用停止を確認できなかったと報告した場合も、ローカルファイルは削除されています。**マシン** を開き、該当するマシンを削除します。
