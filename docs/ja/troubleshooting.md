# トラブルシューティング

作業が止まった箇所から確認します。ログインや支払いの場合は、その画面のメッセージを読みます。マシンの問題なら、そのマシンのターミナルを確認します。作業なら **作業一覧** で該当する項目を開き、**実行されていない理由** を読みます。自分で対応する必要があるか、自動で再開するかが分かります。

## アカウントに再びアクセスする

| 表示や状況 | 対処方法 |
| --- | --- |
| 船長 ID が使用済み、または当日の登録枠がいっぱい | 別の空いている ID を試します。当日の無料登録枠が埋まっていたら、翌日に試します。有料の ID は、元の **引き換えリンク** を使って登録を完了します。 |
| パスワード入力後に **本人確認** が表示された | 認証アプリを使うか、ペアリング済みのマシンで `sail confirm` を実行し、コードを入力します。番号での確認が表示される場合は、確認済みのブラウザーで表示された数字を選びます。最新のログインリクエストを使います。期限切れになったら、ログインし直します。 |
| ログインに何度も失敗した、または使用済みの認証コードを使った | 15 分以内に 5 回失敗すると、既定では 15 分間ロックされます。表示された時間まで待ちます。認証アプリのコードを使用済みなら、次のコードを待ちます。 |
| パスワードを忘れた、または復旧コードが期限切れになった | ペアリング済みのマシンのターミナルで `sail recover` を実行します。**パスワードをお忘れですか?** を選び、表示された船長 ID と 8 文字のコードを入力します。コードは 10 分間有効で、1 回だけ使えます。同じマシンで新しいコードを発行すると、古いコードは無効になります。マシンの認証情報が拒否されたら、ペアリング済みの別のマシンを試します。使えるマシンがなければ、新しい ID の登録が必要です。 |
| **アカウント復旧の反映待ち** | ペアリングから 72 時間未満のマシンでは、認証情報を入れ替える修復をした場合も含め、72 時間の待機が必要です。それ以前にペアリングしていて、2 段階認証を有効にしてから 72 時間以上経っている場合は、すぐに復旧するために認証アプリのコードが必要です。コードがなければ、72 時間の復旧リクエストを送信します。表示された時刻まで待ちます。自分で復旧を依頼していない場合は、ログイン済みの端末で **今回の復旧を取り消す** を選びます。 |

## マシンやチームを動作させる

- Git がなくインストールが止まった場合は、Git をインストールし、**新しいマシンをペアリング** のコマンドを再実行します。Claude Code や Codex が未ログインでも、ペアリングは完了できます。チームに作業を頼む前に、そのマシンで `claude login` または `codex login` を実行します。
- ペアリングコードが期限切れになったら、`sail login` で新しいコードを取得します。**新しいマシンをペアリング** で入力して **ペアリング** を選び、マシン名と **キーコード** をターミナルで確認してから **マシンの承認** を選びます。コードが違う場合はキャンセルしてやり直します。承認後はマシンが接続するまで待ちます。
- マシンが 10 分以内に接続しない場合は、`sail host status` を実行します。サービスの状態とログのパスが表示されます。同じアドレスでサービスを復旧するには `sail login` を実行します。`origin_mismatch` が表示され、アドレスを切り替える場合は、`sail uninstall` で作業用コピーを含むローカルの SailorBridge データが削除されます。その後、接続先アプリの **マシン** 画面でインストールコマンドを取得し、実行してペアリングし直します。
- 更新に失敗した場合は **マシン** で対象のマシンを開き、表示された理由と修復コマンドに従います。ダウンロードの失敗なら後で `sail upgrade` を再実行します。書き込みに失敗した場合はディスク容量を確認し、`sail` をインストールしたアカウントを使います。
- チーム作成時にマシンを求められたら、ペアリングして **オンライン** になるまで待ちます。チームの最後のマシンを外せない場合は、先に **マシンを追加** を使います。チームのディレクトリを作成できない場合は **チーム設定でディレクトリを変更** を選びます。エラーが出たマシン上の絶対ディレクトリパスを使います。同じパス上にファイルがある、書き込み権限がない、ディスクが読み取り専用であるなどの理由で作成できない場合があります。[マシン](machines.md) · [チーム](teams.md)

## チャットで回答を得る

- **リーダー** のマシンがオフラインなら、チームチャットのメッセージは保存され、再接続時に届きます。チームに使えるマシンがなければ、追加してメッセージを送り直します。
- エンジンにログインが必要なら、表示されたマシンでログインします。**リーダー** が使えるアカウントがすべて利用枠を使い切っていたら、リセット時刻の後にメッセージを送り直します。モデルが拒否されたら、案内に従ってエンジンを更新して再試行するか、利用できるアカウントとモデルを選びます。[エンジンアカウントと実行ペース](engine-accounts-and-pacing.md)
- メッセージが **リーダー** への指示ではなく質問への回答になった場合は、開いている質問に答えるか、そのカードで **停止** を選びます。その後、メッセージを送ります。確認カードが置き換わったり回答済みになったりしている場合は、最新のカードや作業を確認してから操作します。
- ファイルが拒否されたら、チームチャットで 1 メッセージにつき 4 個まで、各 5 MiB 以下で送ります。対応形式は PNG、JPEG、WebP、PDF、プレーンテキスト、Markdown です。使えない添付ファイルは選び直します。未送信のアップロードは 24 時間で期限切れになります。アカウントの上限 1 GiB に達したら、送信済みのファイルが 30 日後に期限切れになり、空きができるまで待ちます。メッセージが大きすぎる場合は、各 64 KiB 以下に分けて送ります。
- Agent セッションでアカウントにログインや利用枠が必要だった場合は、先に対応してから **再開** を選びます。チーム間のセッションがラウンド上限に達したら、受け手は 10 または 20 ラウンド延長するか、**ラウンド数無制限** を選べます。開始した側は受け手の操作を待ちます。[チャット](chat.md)

## 作業が待機する理由を調べる

**作業一覧** で作業を開きます。何かを再開するか決める前に、**実行されていない理由** を読みます。

| 作業が止まっている理由 | 対処方法 |
| --- | --- |
| 割り当てが一時停止中、またはこの作業が一時停止中 | チーム全体は **割り当てを再開** を、個別の作業は **再開** を使います。 |
| マシンが使用中、チームが作業数の上限に達している、またはプランが Agent 数の上限に達している | 枠が空くと作業が始まります。チームでは **同時に実行する作業数**、アカウントでは **同時実行の上限** を **サブスクリプション** で確認します。 |
| 書き手とレビュー担当が必要 | **アカウントへ** を選びます。チームのマシン 1 台で、両方のステップに必要なアカウントが有効か確認します。書き手とレビュー担当が別のマシンにいる場合、1 件の作業を一緒に実行できません。 |
| マシンが実行ペースの上限に達した、または利用枠を使い切った | 表示された見込み時刻まで待ちます。ペースによる待機では、**制限なしに切り替え** を確定すると全チームのペース設定が変わります。利用枠を使い切った場合は再確認を行い、利用枠が戻ると同じマシンで再開します。 |
| 回答または前提となる作業が必要 | 自分への質問なら **回答する** を選びます。回答を 5 分間待つと、作業は枠を解放します。回答後は、元のマシンが空き次第続行します。前提となる作業がある場合は、表示された番号の作業を開いて結果を確認します。 |
| マシンが作業を辞退した、または接続を失った | 作業の下に表示される理由を読みます。実行可能な別のマシンが辞退された作業を引き受けられます。候補がすべて辞退した場合は **マシンのメモ** で理由を確認します。実行中のマシンの接続が切れた場合は、そのマシンが先に戻れば再開できます。引き受けた状態が 30 分間更新されないと、別のマシンが最初から実行できます。 |
| **未完了** または **失敗** | **納品レポート** で最後のステップ、理由、保存された成果を確認します。報告された問題を解決します。**続行** が表示される場合は成果を使って同じ作業を再開し、最初からやる場合は **やり直す** を使います。プッシュに失敗した場合は、ローカルに残った成果のブランチ、コミット、プッシュ用コマンドがレポートに表示されます。 |

## コマンド、定時イベント、メモリ項目の問題を解決する

- ターミナルに「このコマンドはジョブまたはチームリーダーのセッションの中で実行してください。」（`local_team_context_missing`）と表示されたら、チームのディレクトリでも、コマンドには進行中のセッションが必要です。チームチャットで **リーダー** に依頼するか、**作業一覧**、**定時イベント**、**チームメモリ** を開いて既存の項目を操作します。[番号付きのチーム項目向けのコマンド](commands.md#番号付きのチーム項目を操作する)
- スラッシュコマンドが認識されない場合は、`/` と入力して有効なフローを表示します。番号の参照先が見つからない場合は、チームと項目の種類を確認し、チャットでは番号の前に `#` を付けます。`sail exec` で対象がオフラインと表示された場合、そのコマンドは開始されていません。開始した*後*に結果が失われた場合は、やり直す前に対象マシンを確認します。[コマンド](commands.md)
- 定時イベントが拒否されたら、1 回限りのイベントには未来の時刻を、繰り返すイベントには 5～720 分の間隔を指定します。1 チームにつき最大 20 件です。不要なイベントを削除して枠を空けます。完了した 1 回限りのイベントを再び実行するには、新しく作り直します。無効なフローや存在しない番号を参照している場合は、次回に向けてメッセージを直します。[フローと定時イベント](flows-and-scheduled-events.md)
- メモリの変更が拒否されたら **チームメモリ** を開きます。ロックされた項目はそこで自分で変更できます。他の人が先に変更した場合は、保存前に最新の本文を読みます。ピン留めの上限に達している場合は、別の項目のピン留めを解除するか、本文を短くしてから追加します。[チームメモリ](team-memory.md)

## 完了していない支払いを確認する

支払いが保留中の場合は、再び支払う前に、元の購入に戻って状況を確認します。サブスクリプションに **支払い失敗** と表示された場合は、**支払い方法を更新して未払い分を支払う** で未払い額の決済画面を開けます。[プランと請求](plans-and-billing.md)

## うまくいかないとき

問題が続く場合は、手順、正確なメッセージ、期待した結果、発生した場所を記録します。分かる範囲でバージョン、マシンの OS、エンジンも添えます。アカウントや支払いの問題は README にある非公開の窓口に連絡します。セキュリティ上の問題は、同じ README にある非公開の報告リンクを使います。認証情報、ペアリングコード、支払い情報、非公開のソースコードは公開の報告に含めないでください。[問題を報告する](README.md#問題を報告する)
