# 役割とルール

各チームには **リーダー** がいます。チームチャットで話しかけると、質問に答え、短いコマンドを実行し、時間のかかる作業をフローに渡します。ワーカーはチームのマシンでフローのステップを実行します。エンジンへの常設の指示はプロジェクトのリポジトリに書きます。役割のエディターとルールのライブラリは利用できません。

## チームに作業を頼む

チームの **チャット** を開きます。「今はどのブランチにいますか？」と聞いてみます。**リーダー** はチームのディレクトリを確認し、会話の中で返信できます。チームの別のマシンを手早く確認するには、`@` と入力してマシンを選び、何を確認するか伝えます。結果の要約が返ります。

納品とレビューが必要な作業は、「セットアップ手順を更新し、レビューを受けてください」のように頼みます。**リーダー** がバックグラウンドのフローを提案したら、カードの作業内容を読みます。キューに入れる場合は **はい、実行**、変更点を伝える場合は **そうではない** を選びます。**作業一覧** を開くと、ワーカーのステップを追えます。ワーカーが判断を必要とするときは、**リーダー** がまずチームにある情報を確認し、自分の回答が必要ならチャットで質問します。

## エンジンに常設の指示を与える

プロジェクト全体への指示は、リポジトリ内の Codex 用の `AGENTS.md`、または Claude Code 用の `CLAUDE.md` に書きます。たとえば、変更を引き渡す前に実行するコマンドを書きます。エンジンはそのリポジトリで作業するときに、対応する指示ファイルを読みます。複数の作業にわたって覚えておいてほしい事実は、チャットで記録を頼むこともできます。[チームメモリ](team-memory.md)

## 間が空いた会話を続ける

同じチームチャットに次のメッセージを送ります。長く間が空いたり、エンジンを変えたり、別のマシンに移ったりした場合は、**リーダー** が新しいエンジンのセッションを開始することがあります。チームに保存された要約、最近のメッセージ、チームメモリ、未完了の作業を引き継ぎます。**会話を整理中…** と表示されても、メッセージを送れます。**リーダー** は要約が終わってから回答します。

## うまくいかないとき

- 以前の詳細が欠けていたら、次のメッセージで作業番号、決定内容、または関連ファイルを伝えます。新しいセッションには、直近の 20 件のメッセージと、要約があればその要約が渡されます。
- 以前の会話の誤った指示が引き継がれ続ける場合は、**チャットをクリア** を選び、チーム名を確認して確定します。過去のメッセージはチャットで非表示になり、次のセッションは古い要約を使わずに始まります。指示がリポジトリ内のファイルやチームメモリにある場合は、そこで修正します。
- **リーダー** が時間切れになった場合は、小さな手順に分けて再度依頼するか、長い依頼を作業として送ります。[コマンド](commands.md)
