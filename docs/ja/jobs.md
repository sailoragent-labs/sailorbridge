# 作業

フローを 1 回実行すると 1 件の作業になります。チームのマシンは 1 つのキューを共有します。チャットで作業を頼み、番号で進捗を調べ、納品レポートで成果と対応が必要な事項を確認できます。

## 作業をキューに入れる

チームチャットでフロー名と依頼内容を送ります。たとえば `/agent Count the files at the top level of this project and report the count.` と送ります。作業がキューに入り、実行できるマシンに空きができると引き受けます。そのマシンは、自分の作業用コピーで作業を実行します。

会話の中で **リーダー** が作業を提案したら、内容を読み、**はい、実行** を選んでキューに入れます。複数のタスクを含む計画では、一覧を確認してから **すべてキューに追加** を選びます。**計画を修正** で変更点を伝えられます。**今は実行しない** を選ぶと、一括のタスクはキューに入りません。承認されると、各タスクに作業番号が付きます。[フローを選ぶ](flows-and-scheduled-events.md)

## 作業を探して状態を確認する

チームチャットの ⋯ メニューで **作業一覧** を選ぶか、チャットに表示された作業の **詳細を見る** を選びます。一覧には最初に **実行中** が表示され、その後はこのブラウザーで最後に使ったフィルターが記憶されます。終了した作業も含めるには **すべて** を選びます。作業内容やフロー名で検索できます。`#6` のようにハッシュ記号を含む番号全体を入力すると、フィルターを問わず検索できます。

| 表示 | 意味 |
| --- | --- |
| **待機** | マシンが作業を引き受けるのを待っています。下の行に理由が表示されます。作業番号が示されている場合は、その前提となる作業の完了を待っています。 |
| **実行中** | マシンが作業を引き受けました。開くと現在の段階とマシンを確認できます。 |
| **リーダー待ち** または **回答待ち** | リーダーが答えられる質問はリーダーが処理します。自分の判断が必要なら **回答する** を選び、チャットで回答します。**あなた** フィルターで自分の回答を待つ作業を探せます。 |
| **完了** | フローが結果を納品しました。**完了、チェック不合格** は、納品はされたものの失敗したチェックがあることを示します。成果を使う前にチェックを確認します。 |
| **未完了** | 依頼されたものをすべて納品する前に停止しました。止まった箇所と不足分を確認します。すでに作成した成果は保持されます。 |
| **失敗** | エラーで実行が終了しました。レポートと **マシンのメモ** を開いて理由を確認します。 |
| **中止** | 作業が停止されました。項目は一覧で引き続き確認できます。 |

**一時停止中** や **枠待ち** でも作業が待機する場合があります。**実行されていない理由** を開いて何を待っているか、対応できる操作があるかを確認します。

## 作業の詳細、納品レポート、使用量を確認する

番号が付いた行を選びます。**作業の詳細** に状態、**実行**、**ラウンド数** が表示されます。**タスク情報** にはマシン、開始した人、**待機** が含まれます。**ステップ** を展開すると、実行された段階と所要時間、使われたエンジンとモデルが表示されます。**品質の問題** が表示されている場合は、自己レビュー、独立レビュー、最後の独立レビューのラウンドからの指摘を確認できます。

作業が終了したら **納品レポート** を開きます。**変更内容**、**検査**、**レビュー指摘**、**未確認**、**判断が必要** を確認します。完了した作業のチェックに失敗があれば、そのチェックが先頭に表示されます。コミットが作成された場合は、反映先を確認します。マシンがプッシュできなかった場合は、ローカルのブランチ、コミット、理由、実行できるコマンドが表示されます。報告だけを行う作業は、コミットなしで回答を納品できます。

**使用量** を開いて **ラウンド別** を展開すると、トークン数と実際に使ったモデルを確認できます。使用量は提供元、アカウント、モデルごとに記録されます。納品レポートの合計は、マシンが最後に作業を引き受けた時点からの分です。キューでの待ち時間は実行時間と別に記録されます。

## 作業を一時停止、変更、停止、再開する

- キューに入っている作業で **一時停止** を選ぶと、マシンが引き受けなくなります。実行できるようになったら **再開** を選びます。**今すぐ開始** で作業をキューの先頭に移動できます。枠が埋まっている場合は、そのまま待つか、実行中の作業を明示的に停止して枠を空けます。
- 未終了の作業を変更するには、作業画面で **チャットへ** を選びます。作業番号が入力されます。新しい要件を追加して送ります。リーダーから変更案が出たら **はい、変更** を選びます。キューに入っている作業なら、そのまま依頼内容が更新されます。実行中なら現在の実行を止めて、同じ番号でキューに戻ります。
- 作業を終了するには、**停止** を選んで確定します。明示的に停止した作業を続けるには、自分の指示が必要です。終了した作業に再開地点と使用可能な成果が残っている場合は、⋯ から **続行** を選びます。同じ作業番号と、保持された作業用コピーまたはプッシュ済みのブランチを使います。続行する前に要件を変えると、最初から実行します。
- **やり直す** を選ぶと、元のフロー、依頼内容、リポジトリ、オプションで新しい作業がキューに入ります。新しい番号が付き、前の作業も引き続き読めます。**続行** が使えない場合に利用します。**削除** を確定すると、終了した作業の記録が完全に削除されます。

## うまくいかないとき

- チーム全体の割り当てが一時停止している場合は、新しい作業を引き受けられるように **割り当てを再開** を選びます。チームかアカウントが同時実行の上限に達している場合は、枠が空くと作業が始まります。[チームの割り当て設定](teams.md)
- 回答を待つ作業には、最初の 5 分が過ぎても返信できます。5 分経つとマシンが枠を解放します。回答後に同じマシンが空くと、作業が再開します。
- 書き手やレビュー担当が必要な作業では、**アカウントへ** を選びます。作業全体に必要なアカウントが 1 台にそろっている必要があります。すべての候補マシンが辞退すると作業は失敗し、各マシンの理由がメモに表示されます。利用枠やペースによる待機の場合は、見込み時刻を確認します。利用枠が戻るか、実行枠が空くと作業が再開します。[エンジンアカウントと実行ペース](engine-accounts-and-pacing.md)
- マシンとの接続が切れても、再接続できれば再開できます。作業を引き受けた状態が 30 分間更新されないと、別のチームマシンが作業を引き受けて最初から実行できます。同じ作業で 3 回接続が切れると **失敗** で終了します。続行ややり直しの前にマシンを確認します。[マシンを確認する](machines.md)
- 復旧可能なシステム障害では、1 件の作業につき最大 10 回まで自動で続行できます。終了したままなら、最後のレポートを読み、原因に対処し、表示されていれば **続行** を使います。
