# 故障排查

从工作停下的地方查起。登录或付款有问题时，请阅读相应页面的消息。机器有问题时，检查该机器上的终端。任务有问题时，打开 **任务列表**，选择任务并阅读 **为什么没在跑**。那里会告诉你是否需要操作，还是任务会自行恢复。

## 恢复账号访问

| 显示内容 | 操作 |
| --- | --- |
| 船长号已被占用，或今天的注册名额已满 | 试试另一个可用号码。如果当天的免费注册已达上限，明天再来。对于付费号码，使用原来的 **兑付链接** 完成注册。 |
| 输入密码后出现 **确认是你** | 使用验证器，或在已配对机器上运行 `sail confirm` 并输入它显示的验证码。如果页面提供数字确认，也可以在已识别的浏览器中点选显示的数字。使用最新的登录请求。请求过期时，请重新登录。 |
| 登录失败次数过多，或验证器验证码被重复使用 | 15 分钟内失败 5 次后，默认锁定 15 分钟。等到显示的时间。如果验证码已用过，请等下一个。 |
| 忘记密码，或恢复码已过期 | 在已配对机器的终端运行 `sail recover`。选择 **忘了密码?**，输入命令显示的船长号和 8 位恢复码。恢复码有效期为 10 分钟，只能使用一次。同一机器的新码会替换旧码。如果机器的凭证被拒绝，请换另一台已配对的机器。没有可用的配对机器时，需要注册新号码。 |
| **账号找回等待生效** | 配对未满 72 小时的机器需要等待 72 小时，修复换过凭证的机器也一样。较早配对的机器上，如果两步验证已启用至少 72 小时，需要验证器验证码才能立即恢复。没有验证码时，提交 72 小时恢复申请。等到页面显示的时间。如果不是你申请的，请在已登录设备上选择 **取消这次找回**。 |

## 让机器或团队恢复工作

- 如果安装因缺少 Git 而停止，请安装 Git，再运行 **配对新机器** 中的安装命令。Claude Code 或 Codex 未登录时，仍可完成配对。请先在机器上运行 `claude login` 或 `codex login`，再要求团队工作。
- 配对码过期时，运行 `sail login` 获取新码。在 **配对新机器** 上输入配对码，选择 **配对**，核对页面上的机器名和详细信息。首次配对时阅读并接受提示，然后选择 **批准机器**，等待机器连接。
- 如果机器在 10 分钟内未连接，运行 `sail host status`，查看服务状态和日志路径。要恢复同一地址的服务，运行 `sail login`。遇到 `origin_mismatch` 且确实要切换地址时，`sail uninstall` 会删除本机 SailorBridge 数据，包括任务的工作副本。然后运行目标应用的 **机器** 页中的安装命令，重新配对。
- 更新失败时，在 **机器** 打开对应机器，按显示的原因和修复命令处理。如果下载失败，稍后用 `sail upgrade` 重试。如果写入失败，请检查磁盘空间，并使用当初安装 `sail` 的账号。
- 如果建团要求有机器，请配对一台并等待 **在线**。如果无法移除团队最后一台机器，请先用 **加一台机器**。如果无法创建团队目录，选择 **去团队设置改目录**。请使用报错机器上的绝对目录路径。路径上已有文件、缺少写权限或磁盘只读都可能导致无法创建。[机器](machines.md) · [团队](teams.md)

## 在聊天中得到回答

- 如果 **小组长** 的机器离线，团队聊天室会保存消息，等机器重新连接后送达。如果团队没有可用机器，请添加一台后重发消息。
- 如果引擎需要登录，请在指定机器上登录。如果 **小组长** 能用的账号都已用尽额度，请在重置时间后重发消息。如果模型被拒绝，按提示更新引擎后重试，或者选择可用的账号和模型。[引擎账号与限速](engine-accounts-and-pacing.md)
- 如果消息被用来回答问题，未送到 **小组长**，请回答当前问题，或选择问题卡上的 **停**。然后再发送消息。如果确认卡已被替换或已经回答，操作前先检查最新的卡片或任务。
- 如果文件被拒绝，请使用团队聊天室，每条消息最多发送 4 个附件，每个最大 5 MiB。支持 PNG、JPEG、WebP、PDF、纯文本和 Markdown。附件无法使用时，重新选择。未发送的上传文件在 24 小时后过期。达到账号的 1 GiB 上限时，请等待已发送文件在 30 天后过期，释放空间。消息过大时，把文字拆成每条最多 64 KiB 的消息。
- 在 Agent 会话中，如果账号需要登录或额度，请先处理，再选择 **恢复**。如果团队间会话已达到轮数上限，接收方可以延长 10 或 20 轮，或选择 **不限回合**。发起方需等待接收方。[聊天](chat.md)

## 查明任务为何在等

在 **任务列表** 中打开任务。决定是否重启前，先阅读 **为什么没在跑**。

| 任务受阻的原因 | 操作 |
| --- | --- |
| 派发已暂停，或此任务已暂停 | 整个团队用 **恢复派发**，单个任务用 **恢复**。 |
| 机器繁忙、团队已达任务上限，或套餐已达 Agent 上限 | 有空位后会开始。查看团队的 **同时跑几件**，或在 **并发上限** 所在的 **订阅** 页面核对账号的上限。 |
| 任务需要写手和审查者 | 选择 **去账号**。确保团队中有一台机器为两个步骤都启用了所需账号。写手和审查者分处不同机器时，无法一起运行同一件任务。 |
| 机器已达到限速线或用完额度 | 等待显示的预估时间。如果因限速等待，确认 **切到不限速** 后会更改所有团队的速度设置。如果额度已用完，任务会重新核对额度，并在额度恢复后于同一机器上继续。 |
| 任务需要答案或前置任务 | 如果问题要你回答，选择 **去作答**。等待回答 5 分钟后，任务会释放空位。回答后，原机器有空时会继续。若在等前置任务，打开显示的任务编号并查看结果。 |
| 机器拒绝任务或停止报到 | 阅读任务下方的原因。其他符合条件的机器可以领取被拒绝的任务。如果所有候选机器都拒绝，打开 **机器的备注** 查看各自的原因。如果运行中的机器失联，而它率先恢复连接，则可继续。30 分钟未续期后，另一台机器可以从头开始。 |
| **未完成** 或 **失败** | 打开 **交付单**，查看最后一个步骤、原因和保留的成果。处理报告的问题。如果能选 **继续**，可沿用保留的成果继续原任务；也可选择 **重做** 重新开始。推送失败时，报告会给出保留在本地的分支、提交和推送命令。 |

## 修复命令、定时事件或记忆条目

- 如果终端显示“请在任务或小组长会话中执行此命令。”（`local_team_context_missing`），即使身处团队目录，该命令也需要正在运行的会话。请在团队聊天室向 **小组长** 提出请求，或打开 **任务列表**、**定时事件**、**团队记忆** 操作现有条目。[操作带编号的团队条目](commands.md#操作带编号的团队条目)
- 无法识别斜杠命令时，输入 `/` 查看已启用的流程。找不到编号引用时，核对团队和条目类型，在聊天中于编号前写上 `#`。如果 `sail exec` 报告目标离线，命令还未启动。如果是启动*之后*丢失结果，请先检查目标机器再重试。[命令](commands.md)
- 如果定时事件被拒绝，请为一次性事件选择未来时刻，或为重复事件选择 5–720 分钟的间隔。每个团队最多可有 20 个事件。删除不需要的事件腾出名额。已完成的一次性事件需要重新创建才能再运行。如果事件引用了已停用的流程或不存在的编号，请修改下次运行要用的消息。[流程与定时事件](flows-and-scheduled-events.md)
- 如果记忆改动被拒绝，打开 **团队记忆**。你可以在那里修改锁定条目。如果其他人先改过，保存前先读最新正文。置顶用量已满时，先取消一条置顶或缩短条目，再置顶另一条。[团队记忆](team-memory.md)

## 检查未完成的付款

付款仍在处理中时，请回到原订单查看状态，再决定是否付款。如果订阅显示 **扣款失败**，**更新付款方式并支付欠款** 会打开结账页来结清欠款。[套餐与账单](plans-and-billing.md)

## 遇到问题时

如果问题仍在，请记下操作步骤、确切消息、预期结果，以及发生问题的位置。如果知道，请附上版本、机器操作系统和引擎。账号或付款问题请使用 README 中的私下联系方式。安全问题请使用其中的私下安全报告链接。不要在公开报告中提交凭证、配对码、付款详情或私有源代码。[报告问题](README.md#报告问题)
